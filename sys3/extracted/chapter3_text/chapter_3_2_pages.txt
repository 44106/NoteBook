        Q4: Write Strategy-- Write Hit
        • write-through
             • On a write hit, data is written simultaneously to both the cache and the main
               memory.
             • Ensures strong data consistency; every write reaches main memory immediately.
             • Cache control bit: only a valid bit
             • memory always have latest data
             • Typical Use Case: Real-time systems (e.g., flight control), where data integrity is
               critical .
§3.3 Four Questions for Cache Designers



        Q4: Write Strategy-- Write Hit
        • write-back
             • On a write hit, data is written only to the cache.
             • The main memory is updated only when the modified (dirty) block is evicted
               from the cache.
             • Uses a dirty bit to track modifications; reduces memory bandwidth usage.
             • Cache control bits: both valid and dirty bits.
             • Typical Use Case: General-purpose processors (e.g., desktop CPUs), where
               performance is prioritized .

        Q4: Write Strategy
        • Dirty Bit
             • A status bit associated with a cache line that indicates whether the data in the
               cache has been modified but not yet written back to main memory.
             • Essential for Write-Back policy to determine if a write-back is needed during
               eviction.
             • Typical Use Case: All modern CPUs using write-back caching (e.g., Intel Core
               series) .
§3.3 Four Questions for Cache Designers



        Q4: Write Strategy-- Write miss
        • Write allocate
             • On a write miss, the system loads the missed block from main memory into the
               cache, then performs the write operation in the cache.
             • Exploits spatial and temporal locality for future accesses.
             • Typical Use Case: Paired with Write-Back in L2/L3 caches to optimize repeated
               writes.
§3.3 Four Questions for Cache Designers



        Q4: Write Strategy-- Write miss
        • no write allocate (Write around)
             • On a write miss, data is written directly to main memory without loading the
               block into the cache.
             • It is not stored in the cache. Prevents cache pollution from one-time or
               infrequent writes.
             • Typical Use Case: Logging systems or streaming data, where written data is
               rarely read again .
§3.3 Four Questions for Cache Designers



        Q4: Write Strategy-- Write miss
        • write-back + write-allocate
             • On a write miss, the block containing the target address (e.g., 0x1000) is first
               loaded from main memory into the cache.
             • The data is then modified within the cache, and the dirty bit is set.
             • The modified data is written back to main memory only when this cache block is
               eventually replaced.
        • write-through + no write-allocate
             • On a write miss, the data is written directly to the main memory without loading
               the corresponding block into the cache.
             • Since no copy exists in the cache, any subsequent read access to this address will
               result in a cache miss, requiring another access to main memory.

        Write stall & Write buffer
        • Write stall
             • When the CPU must wait for writes to complete during write through
        • Write buffer (for Write-Through Optimization)
             • To avoid stalling on writes, many CPUs use a write buffer.
             • A small buffer that temporarily holds write-through data, allowing the CPU to
               continue execution without waiting for memory writes to complete.
             • Mitigates performance penalty of Write-Through policy.
             • This buffer helps when writes are clustered.
             • It does not entirely eliminate stalls since it is possible for the buffer to fill if the
               burst is larger than the buffer.
