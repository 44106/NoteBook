## 0. 如何学习这门课

这门课不是只学 C++ 语法，而是学“如何用 C++ 写可维护的大程序”。课件主线可以理解为：

1. 先掌握 C++ 程序的基本形式、输入输出、字符串、内存、指针、引用和 `const`。
2. 再把“数据 + 操作”组织成类，理解对象、成员函数、构造函数、析构函数、头文件和源文件。
3. 再学习对象之间如何协作，以及如何通过组合和继承复用已有代码。
4. 再学习多态，也就是“用父类指针或引用调用子类行为”的机制。
5. 再学习拷贝构造、赋值、静态成员和资源管理，避免浅拷贝、重复释放、内存泄漏。
6. 再学习运算符重载、流、模板、STL 和迭代器，让自定义类型像内置类型一样自然使用。
7. 最后学习异常、智能指针、多重继承、命名空间等较高级的工程问题。

你是初学者时，最重要的不是背语法，而是不断问四个问题：

- 这个变量/对象存在在哪里？栈、堆、全局区，还是某个对象内部？
- 谁负责初始化它？构造函数、初始化列表、默认构造，还是赋值语句？
- 谁负责释放它？析构函数、`delete`、智能指针，还是标准库容器？
- 调用函数时，到底调用的是哪个版本？普通重载、虚函数动态绑定、模板实例化，还是运算符重载？

## 1. 第 1 讲 Introduction

底稿：[第 1 讲逐页底稿](pagewise/01_1_Introduction_pagewise.md)

### 1.1 课程目标

课程标题是 Object-Oriented Programming with C++。PPT 明确说这不是单纯学语言语法，而是介绍面向对象程序设计，并建立软件工程基础，目标是能生产和维护 large, high-quality software systems。

换成初学者语言：小程序可以靠“从上到下一堆语句”写完；大程序会有很多文件、很多人、很多版本、很多模块。面向对象的核心价值是把复杂程序拆成对象，每个对象负责一部分状态和行为，然后对象之间通过清晰接口协作。

### 1.2 C++ 的背景和应用

课件强调 C++ 在 TIOBE 等榜单中长期靠前，也列举了很多应用场景。C++ 的核心优势是：

- 高效率：接近底层，适合性能敏感程序。
- 能直接接触机器资源：适合操作系统、嵌入式系统、图形、游戏、数据库、编译器、CAD/CG 等。
- 灵活：同时支持过程式、面向对象、泛型、函数式风格的一部分。
- 工程能力强：支持抽象、访问控制、初始化与清理、模板、标准库。

历史上，Bjarne Stroustrup 在 1980 年代初设计并实现 C++。C++ 继承了 C 的效率和底层能力，也借鉴了 Simula/Smalltalk 中的类、继承、对象等思想。课件还提到 C++03、C++11、C++14、C++17、C++20 等标准演进。

### 1.3 第一段程序

PPT 中的入门程序如下：

```cpp
#include <iostream>
using namespace std;

int main()
{
    cout << "Hello, World! I am " << 18 << " Today!" << endl;
    return 0;
}
```

逐行解释：

- `#include <iostream>`：把输入输出库的声明包含进来。
- `using namespace std;`：让你可以直接写 `cout`、`cin`、`endl`，不用每次写 `std::cout`。
- `int main()`：程序入口。操作系统运行程序时，从 `main` 开始。
- `{ ... }`：函数体。
- `cout << ...`：把内容输出到标准输出。
- `endl`：换行并刷新输出缓冲。
- `return 0;`：告诉系统程序正常结束。

### 1.4 输入输出

课件给出读取整数的例子：

```cpp
#include <iostream>
using namespace std;

int main()
{
    int number;
    cout << "Enter a decimal number: ";
    cin >> number;
    cout << "The number is " << number << endl;
}
```

初学者要区分：

- `cout << x` 是输出，把 `x` 送到屏幕。
- `cin >> x` 是输入，从键盘读入并存入变量 `x`。
- `<<` 和 `>>` 后面会在第 9 讲 Streams 重新深入讲，它们其实是可以重载的运算符。

### 1.5 C++ 相对于 C 的扩展

课件说 C++ builds on C，C 知识有帮助，但 C++ is not C。C++ 可以看作 “better C”，但不能仅按 C 思维写 C++。

C++ 的重要增强包括：

- data abstraction：数据抽象，把数据和操作封装成类型。
- access control：访问控制，用 `public`、`private`、`protected` 控制可见性。
- initialization & cleanup：初始化与清理，用构造函数和析构函数保证对象生命周期。
- operator overloading：运算符重载，让自定义类型能像内置类型一样使用。
- generic programming：泛型编程，通过模板复用算法和容器。
- exception handling：异常处理，把错误处理从正常逻辑中分离。

## 2. 第 2 讲 Using Objects

底稿：[第 2 讲逐页底稿](pagewise/02_2_Using_Objects_pagewise.md)

### 2.1 `std::string`

课件从“如何安全读字符串”进入 `std::string`。C 语言常用 `char[]`，容易越界；C++ 推荐使用 `std::string`。

```cpp
#include <string>
using namespace std;

string str1;
string str2 = "jaguar";
```

`string` 支持赋值、拼接、构造、子串、修改和查找：

```cpp
string str3 = str1 + str2;
str1 += str2;

string s("abcdef");
string part = s.substr(2, 3); // 从下标 2 开始取 3 个字符

s.assign("hello");
s.insert(1, "XX");
size_t pos = s.find("ll");
```

关键点：

- `string` 是类，不是基本类型，但可以像变量一样定义和赋值。
- `+`、`+=`、`find`、`substr` 等都是 string 类提供的接口。
- `std::string` 会自动管理内部字符数组，通常比手写 `char*` 安全。

### 2.2 文件输入输出

PPT 中写了文件 I/O：

```cpp
#include <fstream>
using namespace std;

ofstream file1("C:\\test.txt");
file1 << "hello";
```

注意标准头文件通常是：

- `#include <fstream>`
- `ifstream`：从文件读。
- `ofstream`：向文件写。

文件流本质上也是“流”，第 9 讲会系统讲。

### 2.3 内存模型

课件把变量放到 global data、stack、heap 等区域理解：

- 全局区/静态区：全局变量、静态全局变量、静态局部变量。
- 栈：函数调用时的局部变量，生命周期随作用域结束。
- 堆：用 `new` 动态申请的内存，需要 `delete` 释放。

例子：

```cpp
int i;          // global variable
static int j;   // static global variable

void f() {
    int k;              // stack
    static int s;       // static storage
    int* p = new int;   // heap object, p itself is stack variable
    delete p;
}
```

### 2.4 全局变量、`extern` 和 `static`

全局变量是在函数外定义的变量，可以跨函数使用。跨 `.cpp` 文件使用时，要用 `extern` 声明：

```cpp
// a.cpp
int g_count = 0;

// b.cpp
extern int g_count;
```

`extern` 的含义是：这个变量在整个程序的别处有定义，这里只是声明它。

文件作用域的 `static` 会限制名字只在当前 `.cpp` 文件可见：

```cpp
static int file_local = 0;
static void helper() {}
```

所以本讲对 `static` 的总结是：

- global stuff：访问限制。
- local stuff：持久性。

### 2.5 静态局部变量

```cpp
void counter()
{
    static int n = 0;
    n++;
    cout << n << endl;
}
```

`n` 只初始化一次，每次进入函数时保留上次的值。它不是普通局部变量，生命周期贯穿整个程序。

### 2.6 指向对象的指针

```cpp
string s = "hello";
string* ps = &s;
```

这里：

- `&s`：取地址。
- `ps`：保存地址的指针。
- `*ps`：通过指针拿到原对象。
- `ps->size()` 等价于 `(*ps).size()`。

对象和指针的差异：

```cpp
string s;   // s 本身就是一个 string 对象，会被创建和初始化
string* ps; // ps 只是一个指针，它指向哪里还不知道
```

初学者常犯错：定义了指针就以为对象已经存在。实际上指针只是地址变量，不自动创建它指向的对象。

### 2.7 动态内存：`new` 和 `delete`

```cpp
int* p = new int;
int* a = new int[10];
Student* q = new Student();

delete p;
delete[] a;
delete q;
```

规则：

- `new int` 配 `delete`。
- `new int[10]` 配 `delete[]`。
- `new Student()` 会调用构造函数。
- `delete q` 会调用析构函数。

PPT 的 tips：

- 不要 `delete` 不是 `new` 出来的内存。
- 不要对同一块内存连续 `delete` 两次。
- 对空指针 `delete` 通常没问题，但对野指针 `delete` 很危险。
- 动态数组必须用 `delete[]`。

现代 C++ 中，优先使用 `std::vector`、`std::string`、`std::unique_ptr`、`std::shared_ptr`，减少裸 `new/delete`。

### 2.8 引用

引用是 C++ 新的数据类型，可以理解为“已有对象的别名”：

```cpp
int x = 47;
int& y = x;
y = 10; // x 也变成 10
```

规则：

- 引用定义时必须初始化。
- 初始化后绑定不再改变。
- 给引用赋值不是改变引用绑定，而是改变它引用的对象。
- 引用不能为 null。
- 不能有引用的引用。
- 不能有指向引用的指针，例如 `int&* p` 非法。

引用和指针对比：

| 项目 | 引用 | 指针 |
|---|---|---|
| 是否可为空 | 不可以 | 可以是 `nullptr` |
| 是否必须初始化 | 必须 | 不必须 |
| 是否能改指向 | 不能 | 可以 |
| 使用语法 | 像普通变量 | 需要 `*`、`->` |

### 2.9 `const`

`const` 表示常量：

```cpp
const int x = 123;
x = 27; // illegal
```

常量遵守作用域规则。编译期常量常用于数组大小：

```cpp
const int bufsize = 1024;
char buffer[bufsize];
```

运行期常量是运行时才知道值，但初始化后不能改。

### 2.10 指针和 `const`

这是初学者最容易混乱的地方。口诀：`const` 修饰它左边的东西；如果左边没有东西，就修饰右边的东西。

```cpp
const string* p1 = &s; // 指向 const string 的指针：不能通过 p1 改 string
string const* p2 = &s; // 与 p1 一样
string* const p3 = &s; // const 指针：p3 不能改指向，但可改 *p3
const string* const p4 = &s; // 指针和对象都不能通过它改
```

课件强调：

- 可以把非 const 对象当 const 用。
- 不应把 const 对象当非 const 用。
- 字符串字面量本质上应视为 `const char*`。

### 2.11 参数传递

课件最后讲“传地址”和“传 const 引用”：

- 大对象按值传递会复制，成本高。
- 传指针可以避免复制，但被调函数可能改原对象。
- 传 `const T&` 常用于大对象只读参数，既避免复制，又防止修改。

推荐：

```cpp
void printPerson(const Person& p);
```

## 3. 第 3 讲 Class

底稿：[第 3 讲逐页底稿](pagewise/03_3_Class_pagewise.md)

### 3.1 从 C 的 `struct` 到 C++ 的 `class`

PPT 先用点 `Point` 举例：

```cpp
typedef struct point {
    int x;
    int y;
} Point;
```

C 风格中，数据和操作分离：

```cpp
void move(Point* p, int dx, int dy)
{
    p->x += dx;
    p->y += dy;
}
```

C++ 风格把操作放进类型内部：

```cpp
class Point {
public:
    void init(int x, int y);
    void move(int dx, int dy);
    void print() const;

private:
    int x;
    int y;
};
```

成员函数定义：

```cpp
void Point::move(int dx, int dy)
{
    x += dx;
    y += dy;
}
```

`Point::move` 表示 `move` 是 `Point` 类作用域里的函数。

### 3.2 对象 = 属性 + 服务

课件用公式讲：

- Data：属性或状态。
- Operations/Services：函数或行为。

对象不是“只有数据”，也不是“只有函数”。对象把数据和操作数据的函数放在一起。

例如售票机 TicketMachine：

- 属性：票价 `PRICE`、余额 `balance`、总收入 `total`。
- 服务：显示提示、投币、打印票、显示余额、退款。

### 3.3 `this`

`this` 是所有非静态成员函数的隐藏参数，指向调用该函数的那个对象。

```cpp
void Point::print() const
{
    cout << this->x << ", " << this->y << endl;
}
```

当你写：

```cpp
Point a;
a.print();
```

可以理解成编译器暗中传了 `&a` 给 `print`。所以每个对象调用同一个成员函数时，函数通过 `this` 知道自己正在操作哪个对象。

### 3.4 对象和类

类是模板或蓝图，对象是类创建出的具体实体。

课件里的对比：

- Class：定义一类东西有哪些数据和行为。
- Object：具体存在的东西，如某一台售票机、某一个点、某一个学生。

### 3.5 OOP 特征

课件列了 OOP 的核心观点：

1. Everything is an object。
2. A program is a bunch of objects telling each other what to do by sending messages。

这里的“消息”在 C++ 中通常就是成员函数调用：

```cpp
machine.insertMoney(10);
machine.printTicket();
```

### 3.6 `.h` 和 `.cpp`

C++ 中通常一个类拆成：

- `.h`：声明，给别人看接口。
- `.cpp`：定义，实现函数体。

头文件是 interface，是你和使用者之间的 contract。编译器根据声明检查别人是否按正确方式调用。

例子：

```cpp
// Point.h
#ifndef POINT_H
#define POINT_H

class Point {
public:
    Point(int x, int y);
    void move(int dx, int dy);

private:
    int x_;
    int y_;
};

#endif
```

```cpp
// Point.cpp
#include "Point.h"

Point::Point(int x, int y) : x_(x), y_(y) {}

void Point::move(int dx, int dy)
{
    x_ += dx;
    y_ += dy;
}
```

### 3.7 编译单元和链接

课件强调：

- 一个 `.cpp` 文件是一个 compile unit。
- 编译器每次只看一个 `.cpp`，生成一个 `.obj` 或 `.o`。
- 链接器把多个目标文件链接成最终可执行程序。
- `#include` 本质上是在预处理阶段把头文件内容插入当前位置。

所以头文件中一般只放声明，不放普通函数定义，否则多个 `.cpp` include 后会导致重复定义。例外是模板和 inline 函数。

### 3.8 头文件保护

标准头文件结构：

```cpp
#ifndef HEADER_FLAG
#define HEADER_FLAG

// declarations here

#endif
```

作用：防止同一个头文件在一个编译单元中被重复包含。

### 3.9 头文件建议

PPT 的 tips：

- 一个头文件放一个类声明。
- `.h` 和 `.cpp` 文件名通常与类名一致。
- 头文件内容用 include guard 包起来。
- 用 `#include "xx.h"` 包含自己的头文件。
- 用 `#include <...>` 包含标准库头文件。
- CMake 是构建工具，用于组织多文件项目的编译和链接。

## 4. 第 4 讲 Object Interaction

底稿：[第 4 讲逐页底稿](pagewise/04_4_Object_Interaction_pagewise.md)

### 4.1 对象交互

面向对象程序中，对象 send and receive messages。消息由发送者组成，由接收者解释，并由接收者的方法实现。

例子：

```cpp
clockDisplay.start();
ticketMachine.printTicket();
```

发送者只需要知道接口，不应该知道接收者内部如何实现。

### 4.2 封装、抽象、模块化

课件定义：

- Encapsulation：把数据和处理这些数据的方法捆绑在对象里，隐藏数据和动作细节，只暴露公开接口。
- Abstraction：忽略低层细节，关注更高层的问题。
- Modularization：把整体问题划分为模块。

例如时钟显示：

- 方案 A：一个 4 位显示。
- 方案 B：两个 2 位显示，一个负责小时，一个负责分钟。

面向对象更倾向于方案 B，因为 `ClockDisplay` 可以组合两个 `NumberDisplay`，职责更清楚。

### 4.3 类图读法

PPT 中的 ClockDisplay 类图：

```text
ClockDisplay
- hours   : NumberDisplay
- minutes : NumberDisplay
+ start()
+ timeTick()
+ getTime()
```

符号含义：

- `-` 通常表示 private。
- `+` 通常表示 public。
- `hours : NumberDisplay` 表示字段 `hours` 的类型是 `NumberDisplay`。

代码大概是：

```cpp
class ClockDisplay {
private:
    NumberDisplay hours;
    NumberDisplay minutes;
public:
    ClockDisplay();
    void timeTick();
    string getTime() const;
};
```

### 4.4 构造函数

构造函数保证对象创建时自动初始化：

```cpp
class X {
public:
    X(); // constructor
};
```

特点：

- 名字和类名相同。
- 没有返回类型。
- 对象创建时编译器自动调用。
- 可以有参数。

```cpp
class Tree {
public:
    Tree(int height);
};
```

### 4.5 析构函数

析构函数保证对象销毁时自动清理：

```cpp
class X {
public:
    ~X(); // destructor
};
```

特点：

- 名字是 `~类名`。
- 没有返回类型。
- 没有参数。
- 一个类只能有一个析构函数。
- 对象离开作用域时自动调用。

如果类中申请了资源，如 `new` 出来的内存、文件句柄、锁，析构函数通常负责释放。

### 4.6 存储分配和生命周期

课件强调：

- 编译器在进入作用域时为该作用域分配存储。
- 构造函数调用发生在对象定义位置。
- 析构函数在对象离开作用域时调用。

例子：

```cpp
void f()
{
    X a;       // 到这里才构造 a
    if (...) {
        X b;   // 进入这个块后构造 b，离开块时析构 b
    }
}              // 离开函数时析构 a
```

### 4.7 聚合初始化

数组初始化：

```cpp
int a[5] = {1, 2, 3, 4, 5};
int b[6] = {5};          // 第一个元素为 5，其余为 0
int c[] = {1, 2, 3, 4};  // 编译器推断大小为 4
```

数组元素个数：

```cpp
sizeof c / sizeof *c
```

### 4.8 默认构造函数

default constructor 是可以无参数调用的构造函数：

```cpp
class Y {
public:
    Y();       // default constructor
    Y(float);  // not default alone
};
```

如果类没有任何构造函数，编译器会自动生成默认构造函数。但只要你自己写了构造函数，编译器就不再自动生成无参默认构造，除非你显式写出来。

### 4.9 字段、参数、局部变量

PPT 区分三类变量：

- Field：字段，定义在类里、函数外，保存对象长期状态。
- Parameter：参数，函数调用时传入。
- Local variable：局部变量，只在函数或代码块内部存在。

字段持久存在于对象生命周期内；参数和局部变量只在函数调用期间存在。

如果名称冲突，常用 `this->` 或命名约定区分：

```cpp
class Point {
    int x;
public:
    void setX(int x) {
        this->x = x;
    }
};
```

### 4.10 初始化列表

构造函数可以用初始化列表：

```cpp
class Student {
private:
    string name;
public:
    Student(string s) : name(s) {}
};
```

和赋值写法不同：

```cpp
Student::Student(string s) : name(s) {} // 初始化
Student::Student(string s) { name = s; } // 先默认构造，再赋值
```

必须用初始化列表的情况：

- `const` 成员。
- 引用成员。
- 没有默认构造函数的成员对象。
- 基类构造。

### 4.11 函数重载

同名函数可以有不同参数列表：

```cpp
void print(char* str, int width);
void print(double d, int width);
void print(long l, int width);
```

重载根据参数类型和数量选择函数。注意自动类型转换可能产生歧义：

```cpp
void f(int);
void f(double);
f('a'); // 可能因转换产生选择问题
```

### 4.12 默认参数

默认参数在声明中提供：

```cpp
int harpo(int n, int m = 4, int j = 5);
```

规则：默认参数必须从右往左连续提供。

```cpp
int chico(int n, int m = 6, int j); // illegal
```

### 4.13 const 对象和 const 成员函数

如果对象是 const：

```cpp
const Date d(1, 1, 2001);
```

只能调用 const 成员函数：

```cpp
class Date {
public:
    int get_day() const;
    void set_day(int d);
};
```

`const` 成员函数承诺不修改对象：

```cpp
int Date::get_day() const
{
    return day;
}
```

声明和定义处都要写 `const`。

### 4.14 类中的常量

普通 `const int size;` 是对象成员，不一定能当编译期数组大小。若要类内编译期常量，现代 C++ 常用：

```cpp
class HasArray {
    static const int size = 100;
    int array[size];
};
```

### 4.15 inline 函数

函数调用有开销：压参数、跳转、返回。inline 的思想是把函数体展开到调用处：

```cpp
inline int f(int i)
{
    return i * 2;
}
```

适合 inline：

- 小函数，2-3 行。
- 频繁调用，例如循环内部。
- 访问函数 getter/setter。

不适合 inline：

- 大函数。
- 递归函数。
- 修改频繁的复杂函数。

类声明内部定义的成员函数自动是 inline。inline 函数定义可放在头文件中，因为 inline 允许多个定义，但每个定义必须一致。

PPT 还对比了宏和 inline：

```cpp
#define unsafe(i) ((i) >= 0 ? (i) : -(i))

inline int safe(int i)
{
    return i >= 0 ? i : -i;
}
```

宏没有类型检查，可能重复求值；inline 函数更安全。

## 5. 第 5 讲 Composition and Inheritance

底稿：[第 5 讲逐页底稿](pagewise/05_5_Composition_and_Inheritance_pagewise.md)

### 5.1 组合：has-a

Composition 是用已有对象构造新对象。关系是 has-a。

例子：

- Employee has a Name。
- Employee has an Address。
- SavingsAccount has a Person。
- SavingsAccount has a Currency。

代码：

```cpp
class SavingsAccount {
private:
    Person m_saver;
    Currency m_balance;
public:
    SavingsAccount(const char* name, const char* address, int cents)
        : m_saver(name, address), m_balance(0, cents)
    {}
};
```

### 5.2 嵌入对象必须初始化

对象成员会先于外层对象构造函数体被初始化。若不在初始化列表中指定，编译器会尝试调用成员对象的默认构造函数。

所以这两种写法不等价：

```cpp
SavingsAccount::SavingsAccount(...)
    : m_saver(name, address), m_balance(0, cents)
{}
```

```cpp
SavingsAccount::SavingsAccount(...)
{
    m_saver.setName(name); // 这时 m_saver 已经先被默认构造了
}
```

如果 `Person` 没有默认构造函数，第二种甚至无法编译。

### 5.3 嵌入对象通常设为 private

原因：

- 它们是实现细节。
- 新类只应该暴露自己愿意暴露的接口。
- 如果直接 public 暴露成员对象，外部代码会依赖内部结构，后续很难修改实现。

### 5.4 继承：is-a

Inheritance 是从已有类派生新类。关系是 is-a。

例子：

- Manager is an Employee。
- Student is a Person。
- Circle is an Ellipse。

语法：

```cpp
class Manager : public Employee {
    // ...
};
```

public 继承应表示替换原则：如果 B 是 A，那么任何需要 A 的地方都可以用 B。

### 5.5 DoME 示例

PPT 用 Database of Multimedia Entertainment 展示 CD 和 DVD：

- CD 有 artist、number of tracks、playing time、got it、comment。
- DVD 有 director、playing time、got it、comment。
- 二者有大量相同字段和行为。

如果分别写 `CD` 和 `DVD`，会有重复代码。解决方式是抽出公共父类，例如 `Item`，让 `CD` 和 `DVD` 继承它。

类图含义：

```text
Item
  ^
  |
  +-- CD
  +-- DVD
```

`Item` 放公共字段和函数，`CD`、`DVD` 放各自特有字段。

### 5.6 继承和构造函数

把继承来的父类部分想成一个嵌入对象。构造派生类时：

1. 先构造基类部分。
2. 再构造成员对象。
3. 最后执行派生类构造函数体。

析构顺序相反：

1. 派生类析构函数体。
2. 成员对象析构。
3. 基类析构。

例子：

```cpp
Manager::Manager(const string& name,
                 const string& ssn,
                 const string& title)
    : Employee(name, ssn), m_title(title)
{}
```

如果不显式调用 `Employee(name, ssn)`，编译器会尝试调用 `Employee()`。

### 5.7 子类调用父类函数

派生类可以复用基类实现：

```cpp
void Manager::print(ostream& out) const
{
    Employee::print(out);
    out << m_title << endl;
}
```

`Employee::print(out)` 明确调用基类版本。

### 5.8 名字隐藏

PPT 提到：如果在派生类中重新定义某个成员函数名，基类中同名的其他重载版本会被隐藏。

```cpp
class Base {
public:
    void f(int);
    void f(double);
};

class Derived : public Base {
public:
    void f(string);
};
```

此时 `Derived` 中基类的 `f(int)` 和 `f(double)` 可能不可直接见。可用 `using Base::f;` 引入。

### 5.9 访问控制

成员访问：

- `public`：所有客户可见。
- `protected`：派生类和 friend 可见，普通客户不可见。
- `private`：只有本类和 friend 可见。

`class` 和 `struct` 区别：

- `class` 默认 private。
- `struct` 默认 public。

继承方式：

```cpp
class D1 : public Base {};
class D2 : protected Base {};
class D3 : private Base {};
```

public 继承保留接口的 public 性质，最适合表达 is-a。private/protected 继承更多是实现技巧，不表示普通意义上的 is-a。

### 5.10 friend

friend 可以把某个函数或类授予访问 private/protected 成员的权限：

```cpp
class X {
    friend void inspect(const X&);
private:
    int secret;
};
```

friend 由类自己声明，表示“我允许它访问我的内部”。不要滥用 friend，否则会破坏封装。

### 5.11 向上转型 upcasting

public 继承允许从派生类指针/引用转到基类指针/引用：

```cpp
Manager pete("Pete", "444-55-6666", "Bakery");
Employee* ep = &pete;
Employee& er = pete;
```

这叫 upcasting。它安全，因为 Manager 是 Employee。但会丢失静态类型信息：通过 `Employee*` 只能看到 Employee 接口，除非用虚函数实现动态行为。

## 6. 第 6 讲 Polymorphism

底稿：[第 6 讲逐页底稿](pagewise/06_6_Polymorphism_pagewise.md)

### 6.1 多态解决什么问题

绘图程序中可能有 Rectangle、Circle、Ellipse。它们都能 `render()`、`move()`，但每种图形绘制方式不同。

我们希望写：

```cpp
void render(Shape* p)
{
    p->render();
}
```

传入 Rectangle 就画矩形，传入 Circle 就画圆。这就是多态。

### 6.2 虚函数和动态绑定

基类中把函数声明为 `virtual`：

```cpp
class Shape {
public:
    virtual ~Shape();
    virtual void render();
};
```

派生类重写：

```cpp
class Ellipse : public Shape {
public:
    void render() override;
};
```

当通过基类指针/引用调用虚函数时，程序运行时根据对象真实类型选择函数。这叫 dynamic binding。

### 6.3 vptr 和 vtable

课件图示了 C++ 虚函数的大致实现：

- 含虚函数的对象通常有一个隐藏指针 vptr。
- vptr 指向该类的虚函数表 vtable。
- vtable 中保存虚函数入口地址。

所以：

- `Shape` 对象的 vptr 指向 Shape vtable。
- `Ellipse` 对象的 vptr 指向 Ellipse vtable。
- `Circle` 对象的 vptr 指向 Circle vtable。

通过基类指针调用虚函数时，程序沿 vptr 找到正确函数。

### 6.4 对象切片 object slicing

课件问：

```cpp
Ellipse elly(20F, 40F);
Circle circ(60F);
elly = circ;
```

如果 `Circle` 继承自 `Ellipse`，把 Circle 对象按值赋给 Ellipse，只会复制 Ellipse 那部分，Circle 额外部分被切掉。这叫 slicing。

避免方式：

- 多态对象用指针或引用传递。
- 不要按值传递多态基类。

### 6.5 指针赋值和内存泄漏

课件还问：

```cpp
Ellipse* elly = new Ellipse(20F, 40F);
Circle* circ = new Circle(60F);
elly = circ;
```

这样原来 `new Ellipse` 的地址丢了，无法 `delete`，造成内存泄漏。

正确做法是使用智能指针，或先 `delete elly`，但现代 C++ 更推荐 RAII。

### 6.6 引用参数中的虚函数

```cpp
void func(Ellipse& elly)
{
    elly.render();
}

Circle circ(60F);
func(circ);
```

如果 `render` 是虚函数，那么传入 Circle 时会调用 Circle 的 `render`。引用不会切片。

### 6.7 虚析构函数

如果类可能被继承并通过基类指针删除，析构函数应为 virtual：

```cpp
class Shape {
public:
    virtual ~Shape() {}
};

Shape* p = new Ellipse(...);
delete p; // 如果析构函数不是 virtual，可能只调用 Shape 析构
```

这是 C++ 面向对象资源管理的硬规则之一。

### 6.8 overriding

Overriding 是派生类重新定义虚函数的函数体：

```cpp
class Base {
public:
    virtual void func();
};

class Derived : public Base {
public:
    void func() override;
};
```

派生类中仍可调用基类版本：

```cpp
void Derived::func()
{
    cout << "Derived";
    Base::func();
}
```

### 6.9 协变返回类型

课件提到 return types relaxation：如果 `D` publicly derived from `B`，则 `D::f()` 可以返回基类返回类型的派生指针或引用类型。

```cpp
class Expr {
public:
    virtual Expr* clone();
};

class BinaryExpr : public Expr {
public:
    BinaryExpr* clone() override;
};
```

只适用于指针和引用类型。

### 6.10 重载和虚函数

Overloading 是同名不同参数；overriding 是子类重写虚函数。

如果基类有多个重载虚函数，派生类重写其中一个时，其他同名版本可能被隐藏。PPT 建议：override all variants，或用 `using Base::func;`。

### 6.11 不要重定义继承来的非虚函数

非虚函数是静态绑定的，通过基类指针调用时不会动态分派。课件明确提示：

- Never redefine an inherited non-virtual function。
- Non-virtuals are statically bound。

### 6.12 抽象类和接口类

抽象类用于：

- 建模。
- 强制正确行为。
- 定义接口但不实现。

纯虚函数：

```cpp
class Shape {
public:
    virtual ~Shape() {}
    virtual void render() = 0;
};
```

含纯虚函数的类不能直接创建对象。

Protocol / Interface class 的特征：

- 所有非静态成员函数都是纯虚函数，析构函数除外。
- 虚析构函数通常有空实现。

## 7. 第 7 讲 Copy Constructor, static, Container & STL

底稿：[第 7 讲逐页底稿](pagewise/07_7_Copy_Constructor_pagewise.md)

### 7.1 引用作为成员

引用成员必须在构造函数初始化列表中初始化：

```cpp
class X {
public:
    X(int& r) : ref(r) {}
private:
    int& ref;
};
```

不能先默认构造再赋值，因为引用一旦绑定就不能换绑。

### 7.2 返回引用

函数可以返回引用，但绝不能返回局部变量引用：

```cpp
int& bad()
{
    int x = 0;
    return x; // 错，x 离开函数就销毁
}
```

可以返回数组元素、对象成员、静态变量等仍然存在的对象引用。

### 7.3 const 引用参数

课件强调：

- Passing by const value: usually don't do it。
- Passing by const reference：大对象只读传参的常用方式。

```cpp
Person(const string& name, int weight);
```

`const string&` 避免复制，又保证函数不改原对象。

临时值通常只能绑定到 const 引用：

```cpp
void f(const int& x);
f(i * 3); // OK
```

非 const 引用不能绑定临时值。

### 7.4 拷贝构造函数

拷贝构造是用已有对象创建新对象：

```cpp
class T {
public:
    T(const T& other);
};
```

签名必须用引用，否则按值传参会再次触发拷贝构造，形成无限递归。

何时调用：

- 按值传参。
- 用已有对象初始化新对象。
- 函数按值返回对象，虽然编译器可能优化掉。

```cpp
Person baby_a("Fred");
Person baby_b = baby_a; // copy constructor, not assignment

void roster(Person p);  // call by value triggers copy
```

### 7.5 浅拷贝和深拷贝

如果类中有裸指针，默认拷贝构造只做 memberwise copy，可能只复制指针地址。

```cpp
class Person {
    char* name;
};
```

浅拷贝后两个对象指向同一块内存，析构时可能 double delete。

深拷贝需要分配新内存并复制内容：

```cpp
Person::Person(const Person& w)
{
    name = new char[std::strlen(w.name) + 1];
    std::strcpy(name, w.name);
}
```

### 7.6 C 字符串

PPT 复习了 C 字符串：

- 字符数组。
- 以 `'\0'` 或 ASCII null 结尾。
- `"C++"` 在内存中是 `C`、`+`、`+`、`\0`。

标准 C 字符串函数在 `<cstring>`：

```cpp
size_t strlen(const char* s);
char* strcpy(char* dest, const char* src);
int strcmp(const char* a, const char* b);
```

但在 C++ 中，能用 `std::string` 时优先用 `std::string`。

### 7.7 默认拷贝构造何时够用

如果成员本身会正确拷贝，例如 `std::string`，通常不需要自己写拷贝构造：

```cpp
class Person {
    string name;
};
```

默认拷贝构造会递归调用所有成员对象和基类的拷贝构造。这叫 memberwise initialization。

### 7.8 构造、赋值和析构

课件区分：

```cpp
MyType b;
MyType a = b; // initialization, copy constructor
a = b;        // assignment, operator=
```

每个对象应该构造一次、析构一次。资源管理类通常要考虑三件事：

- 析构函数。
- 拷贝构造函数。
- 拷贝赋值运算符。

这就是经典 Rule of Three。

### 7.9 拷贝开销

拷贝可能被编译器优化掉，例如 return value optimization。但程序员不应完全依赖优化。大对象尽量用 `const T&` 传参，返回值依现代编译器通常可接受。

### 7.10 static 的两类意义

PPT 总结 static 两个基本含义：

- Static storage：静态存储，只分配一次，固定地址。
- Visibility of a name：限制名字可见性。

### 7.11 函数内 static

```cpp
void f()
{
    static int count = 0;
    ++count;
}
```

特点：

- 整个程序期间保存值。
- 只初始化一次。
- 作用域仍限于函数内部。

### 7.12 全局 static

```cpp
// file1.cpp
static int s_local;
```

它只在当前文件可见，其他 `.cpp` 即使用 `extern` 也不能访问。

### 7.13 static 对象

静态对象在定义遇到时构造，最多构造一次。全局静态对象在程序开始/结束附近构造和析构，涉及跨文件初始化顺序问题，应谨慎。

### 7.14 static 成员

静态成员变量属于类，而不是某个对象：

```cpp
class Counter {
public:
    static int count;
};

int Counter::count = 0;
```

静态成员函数没有 `this`：

```cpp
class Counter {
public:
    static int getCount();
};
```

静态成员函数只能直接访问静态成员，不能直接访问普通成员，因为没有具体对象。

访问方式：

```cpp
Counter::count;
obj.count; // 语法允许，但不推荐作为主要风格
```

### 7.15 Container & STL 图像页补充

第 7 讲后半部分 62-96 页是图像页，文本层为空，但页面图片显示内容是 STL 入门，和第 11 讲高度重合。主要知识点包括：

- Collection：存放一组对象的容器。
- STL = Standard Template Library，是 ISO 标准 C++ 库的一部分，提供数据结构和算法。
- STL 由 containers、algorithms、iterators 三部分组成。
- 常见容器：`vector`、`list`、`map`。
- `vector` 类似可扩展数组。
- `list` 是链表，示例中用 `list<string>`，支持 `push_back`、`push_front`，遍历时用 `p != s.end()`，不能用 `p < s.end()`，因为链表元素不保证连续存储。
- `map` 保存 key-value 对。
- `typedef` 可简化长类型名，如 `map<Name, list<PhoneNum>>::iterator`。
- C++11 后可用 `auto` 和 `using` 替代很多 `typedef` 场景。
- 使用自定义类放入 STL 容器时，可能需要默认构造、赋值运算符、比较函数等。

这些内容在第 11 讲和第 12 讲会系统讲。

## 8. 第 8 讲 Overloaded Operators

底稿：[第 8 讲逐页底稿](pagewise/08_8_Overloaded_Operators_pagewise.md)

### 8.1 运算符重载是什么

运算符重载让用户自定义类型表现得像内置类型：

```cpp
Complex a, b, c;
c = a + b;
```

本质上，重载运算符只是名字特殊的函数：

```cpp
operator+(...)
```

### 8.2 可以和不可以重载的运算符

可以重载很多一元和二元运算符，如：

```text
+ - * / % ^ & | ~
= -= *= /= %= ^= &= |=
<< >> >>= <<=
== != < > <= >=
[] () -> =
```

不能重载：

```text
.   .*   ::   ?:
sizeof   typeid
static_cast dynamic_cast const_cast reinterpret_cast
```

限制：

- 只能重载已有运算符，不能发明 `**`。
- 不能改变操作数个数。
- 不能改变优先级。
- 不能改变结合性。
- 至少一个操作数通常应是用户自定义类型。

### 8.3 成员函数形式

```cpp
class Integer {
public:
    Integer operator+(const Integer& rhs) const;
private:
    int i;
};
```

调用：

```cpp
x + y;
x.operator+(y);
```

成员函数有隐式第一个参数 `this`。二元运算符成员函数通常只写一个显式参数。

### 8.4 全局函数形式

```cpp
Integer operator+(const Integer& lhs, const Integer& rhs);
```

调用：

```cpp
operator+(x, y);
```

全局函数两个参数都显式出现。它允许左右两边都参与类型转换。若需要访问 private 成员，可声明为 friend。

### 8.5 member vs free function 建议

PPT 建议：

- 一元运算符通常做成员函数。
- `=`, `()`, `[]`, `->`, `->*` 必须是成员函数。
- 其他二元运算符通常做非成员函数，尤其是希望左右操作数都可隐式转换时。

### 8.6 参数传递和 const

如果操作数只读，传 `const T&`，内置类型除外：

```cpp
T operator+(const T& lhs, const T& rhs);
```

不修改对象的成员函数应加 `const`：

```cpp
bool operator==(const T& rhs) const;
```

### 8.7 返回值设计

返回类型取决于运算符语义：

- `operator+` 生成新对象，通常返回值。
- `operator+=` 修改自身，通常返回 `T&`。
- `operator=` 返回 `T&`，支持链式赋值。
- `operator[]` 通常返回引用，支持读写元素。
- 比较运算符返回 `bool`。

### 8.8 常见原型

```cpp
T operator+(const T& l, const T& r);
bool operator==(const T& l, const T& r);
bool operator<(const T& l, const T& r);
```

### 8.9 前置和后置 `++`

区分：

```cpp
Integer& operator++();    // ++x
Integer operator++(int);  // x++
```

后置形式的 `int` 参数只是占位，编译器传 0，用来区分前置和后置。

典型写法：

```cpp
Integer& Integer::operator++()
{
    ++i;
    return *this;
}

Integer Integer::operator++(int)
{
    Integer old(*this);
    ++(*this);
    return old;
}
```

前置返回引用，后置返回旧值副本。

### 8.10 关系运算符

课件建议用少量核心运算符定义其他运算符：

```cpp
bool operator!=(const T& rhs) const { return !(*this == rhs); }
bool operator>(const T& rhs) const { return rhs < *this; }
bool operator<=(const T& rhs) const { return !(rhs < *this); }
bool operator>=(const T& rhs) const { return !(*this < rhs); }
```

### 8.11 `operator[]`

必须是成员函数，通常返回引用：

```cpp
T& operator[](int index);
const T& operator[](int index) const;
```

返回引用才能写：

```cpp
v[0] = 10;
```

### 8.12 赋值运算符

```cpp
T& T::operator=(const T& rhs)
{
    if (this != &rhs) {
        // release old resource
        // copy new resource
    }
    return *this;
}
```

要点：

- 必须是成员函数。
- 返回 `*this` 的引用。
- 检查自赋值。
- 如果类管理动态内存，通常必须自定义赋值运算符和拷贝构造。
- 若要禁止赋值，可将其删除或私有化。

### 8.13 函数调用运算符和仿函数

```cpp
struct F {
    void operator()(int x) const {
        cout << x << endl;
    }
};

F f;
f(10);
```

重载 `()` 的对象叫 functor，可以像函数一样调用，并且能携带状态。

### 8.14 类型转换

单参数构造函数可能产生隐式转换：

```cpp
class PathName {
public:
    PathName(const string& s);
};
```

可用 `explicit` 防止隐式转换：

```cpp
explicit PathName(const string& s);
```

转换运算符：

```cpp
class Rational {
public:
    operator double() const;
};
```

形式：

```cpp
X::operator T()
```

没有返回类型，函数名本身说明转换目标类型。

### 8.15 不要滥用运算符重载

课件提醒：Just because you can overload an operator doesn't mean you should。

只有当重载能让代码更容易读、更符合直觉、更容易维护时才使用。不要让 `+` 做删除文件这种违反直觉的事情。

## 9. 第 9 讲 Streams

底稿：[第 9 讲逐页底稿](pagewise/09_9_Streams_pagewise.md)

### 9.1 为什么要 stream

C 中常用 `printf`、`scanf`，但它们：

- 不是面向对象。
- 不支持用户自定义类型的自然输入输出。
- 格式字符串容易出错。

C++ streams 的优势：

- 类型安全。
- 可重载 `<<` 和 `>>`。
- 支持自定义类型。
- 统一处理键盘、屏幕、文件、字符串等。

### 9.2 什么是 stream

Stream 是对设备的一维、单向逻辑接口。可以把它想成数据流：

- `cin`：从键盘流入程序。
- `cout`：从程序流向屏幕。
- `ifstream`：从文件流入程序。
- `ofstream`：从程序流向文件。

文件可随机访问，但 `cin/cout` 通常不是随机访问。

### 9.3 stream 类

| 用途 | 输入 | 输出 | 头文件 |
|---|---|---|---|
| 标准输入输出 | `istream` | `ostream` | `<iostream>` |
| 文件 | `ifstream` | `ofstream` | `<fstream>` |
| 字符串流 | `istringstream` | `ostringstream` | `<sstream>` |

PPT 中也出现旧的 `istrstream/ostrstream`，现代 C++ 更推荐 `<sstream>`。

### 9.4 extractors 和 inserters

- Extractor：`>>`，从流中读值。
- Inserter：`<<`，向流中写值。

```cpp
int i;
cin >> i;
cout << i;
```

### 9.5 文本流

Text streams 处理 ASCII 或文本字符，可能执行换行转换。例如同样写 `\n`，不同系统文件里实际换行表示可能不同。

### 9.6 预定义流

- `cin`：标准输入。
- `cout`：标准输出。
- `cerr`：标准错误，通常不缓冲。
- `clog`：日志输出，通常缓冲。

### 9.7 自定义输入运算符

必须是二参数自由函数：

```cpp
istream& operator>>(istream& is, T& obj)
{
    // read fields into obj
    return is;
}
```

返回 `istream&` 支持链式输入：

```cpp
cin >> a >> b >> c;
```

### 9.8 自定义输出运算符

```cpp
ostream& operator<<(ostream& os, const T& obj)
{
    // write obj to os
    return os;
}
```

返回 `ostream&` 支持链式输出：

```cpp
cout << a << b << c;
```

### 9.9 其他输入函数

PPT 列了：

- `int get()`：读下一个字符，没字符时返回 EOF。
- `get(char* buf, int limit, char delim='\n')`：读到上限或分隔符，不消耗分隔符。
- `getline(...)`：读一行并消耗换行。
- `gcount()`：返回刚刚读取的字符数。
- `putback(char c)`：把一个字符放回流中。
- `peek()`：查看下一个字符但不消耗。

### 9.10 其他输出函数

- `put(char)`：输出单个字符。
- `flush()`：强制刷新输出缓冲。

```cpp
cout << "Enter a number";
cout.flush();
```

### 9.11 manipulators

Manipulators 修改流状态，需要 `<iomanip>`：

```cpp
cout << setprecision(2) << 1230.243 << endl;
cout << setw(20) << "OK!";
```

常见 manipulator：

| manipulator | 作用 |
|---|---|
| `dec`, `hex`, `oct` | 设置进制 |
| `endl` | 换行并 flush |
| `flush` | 刷新 |
| `setw(int)` | 设置字段宽度 |
| `setfill(ch)` | 设置填充字符 |
| `setbase(int)` | 设置数字基底 |
| `ws` | 跳过空白 |
| `setprecision(int)` | 设置浮点精度 |
| `setiosflags` | 打开 flags |
| `resetiosflags` | 关闭 flags |

### 9.12 自定义 manipulator

```cpp
ostream& tab(ostream& out)
{
    return out << '\t';
}

cout << "Hello" << tab << "World!" << endl;
```

### 9.13 stream flags

PPT 列出：

- `ios::skipws`：跳过前导空白。
- `ios::left`, `ios::right`：对齐。
- `ios::internal`：符号和值之间填充。
- `ios::dec`, `ios::oct`, `ios::hex`：数字格式。
- `ios::showbase`：显示进制前缀。
- `ios::showpoint`：总显示小数点。
- `ios::uppercase`：大写。
- `ios::showpos`：正数显示 `+`。
- `ios::scientific`, `ios::fixed`：浮点格式。
- `ios::unitbuf`：每次写都 flush。

设置方式：

```cpp
cout << setiosflags(ios::showpos);
cout << resetiosflags(ios::showpos);

cout.setf(ios::showpos);
cout.unsetf(ios::showpos);
```

## 10. 第 10 讲 Templates

底稿：[第 10 讲逐页底稿](pagewise/10_10_Template_pagewise.md)

### 10.1 为什么需要模板

如果你需要 `list<int>`、`list<string>`、`list<Person>`，它们结构相同，只是元素类型不同。复制多份代码很糟糕。

模板允许把类型作为参数：

```cpp
template <class T>
```

这就是 generic programming。

### 10.2 函数模板

不用模板时：

```cpp
void swap(int& x, int& y)
{
    int temp = x;
    x = y;
    y = temp;
}
```

模板版本：

```cpp
template <class T>
void swap(T& x, T& y)
{
    T temp = x;
    x = y;
    y = temp;
}
```

`T` 可出现在：

- 参数类型。
- 返回类型。
- 函数内部变量类型。

### 10.3 模板实例化

当你调用：

```cpp
int i, j;
swap(i, j);

float a, b;
swap(a, b);
```

编译器会根据实际类型生成 `swap<int>` 和 `swap<float>` 的函数定义。这叫 instantiation。

### 10.4 模板匹配规则

PPT 强调：

- 模板参数推导只用 exact match。
- 不自动做普通类型转换。

```cpp
swap(intValue, doubleValue); // 模板无法推导同一个 T
```

重载规则：

1. 先找唯一普通函数匹配。
2. 再找唯一函数模板匹配。
3. 普通函数可考虑隐式转换。

### 10.5 显式指定模板参数

如果编译器无法推导，可以显式写：

```cpp
swap<int>(i, j);
```

### 10.6 类模板

```cpp
template <class T>
class Vector {
public:
    Vector(int size);
    T& operator[](int index);
private:
    T* m_elements;
    int m_size;
};
```

使用：

```cpp
Vector<int> v1(100);
Vector<Complex> v2(256);
```

成员函数定义：

```cpp
template <class T>
Vector<T>::Vector(int size) : m_size(size)
{
    m_elements = new T[m_size];
}
```

### 10.7 模板排序例子

```cpp
template <class T>
void sort(Vector<T>& arr)
{
    // bubble sort example
}
```

如果 `T` 是 `int`，需要 `operator<`。如果 `T` 是 `string`，也需要可比较。模板本身不关心具体类型，只要求类型支持所用操作。

### 10.8 多类型模板

```cpp
template <class Key, class Value>
class HashTable {
public:
    const Value& lookup(const Key&) const;
};
```

### 10.9 非类型模板参数

模板参数也可以是常量表达式：

```cpp
template <class T, int bounds = 100>
class FixedVector {
    T elements[bounds];
};
```

使用：

```cpp
FixedVector<int, 50> v1;
FixedVector<int, 10 * 5> v2;
FixedVector<int> v3; // default bounds = 100
```

### 10.10 模板和继承

模板类可以：

- 继承非模板类。
- 继承模板类。
- 被非模板类继承。

```cpp
template <class A>
class Derived : public Base {};

template <class A>
class Derived2 : public BaseTemplate<A> {};
```

### 10.11 CRTP

课件提到 Curiously Recurring Template Pattern：

```cpp
template <class T>
class Base {
public:
    void interface() {
        static_cast<T*>(this)->implementation();
    }
};

class Derived : public Base<Derived> {
public:
    void implementation();
};
```

它用模板模拟某些虚函数效果，常用于泛型编程和静态多态。

### 10.12 写模板的建议

PPT 的流程：

1. 先写非模板版本并工作。
2. 建立好的测试用例。
3. 测性能并调优。
4. 审查实现。
5. 再泛化成模板。

模板的声明和定义通常都放头文件中，因为编译器实例化模板时必须看到完整定义。

## 11. 第 11 讲 STL

底稿：[第 11 讲逐页底稿](pagewise/11_11_STL_pagewise.md)

### 11.1 STL 是什么

STL = Standard Template Library，是 ISO Standard C++ Library 的一部分，提供 C++ 的数据结构和算法。课件提到 Alexander Stepanov。

STL 的好处：

- 减少开发时间，常用数据结构已写好并调试过。
- 提高代码可读性，把精力放在业务逻辑。
- 提供统一接口和成熟算法。

### 11.2 STL 三部分

- Containers：容器，存数据。
- Algorithms：算法，处理数据。
- Iterators：迭代器，连接容器和算法。

这三者的解耦是 STL 的核心设计。

### 11.3 常见容器

顺序容器：

- `vector`：动态数组，随机访问快，尾部插入快。
- `deque`：双端队列，头尾插入较快。
- `list`：双向链表，插入删除不搬移元素，但随机访问慢。
- `forward_list`：单向链表。

关联容器：

- `map`：键值对，按 key 排序。
- `set`：不重复集合。
- `multimap`、`multiset`：允许重复 key 或元素。

适配器：

- `queue`
- `priority_queue`
- `stack`

其他：

- `bitset`
- `valarray`

### 11.4 vector

```cpp
#include <vector>
using namespace std;

vector<int> v;
v.push_back(10);
v.push_back(20);
cout << v[0];
```

基本操作：

- 构造：`vector<Elem> c;`
- 拷贝：`vector<Elem> c1(c2);`
- 元素访问：`v.at(index)`、`v[index]`、`v.front()`、`v.back()`。
- 大小：`v.size()`、`v.empty()`。
- 添加：`v.push_back(x)`。

效率提示：

- 预估容量并 `reserve`，避免反复扩容。
- 避免不必要拷贝。
- `v[index]` 不检查越界，`v.at(index)` 检查越界并可能抛异常。

### 11.5 list

`list` 和 `vector` 有相似概念，但底层是双向链表。

```cpp
#include <list>
#include <string>

list<string> s;
s.push_back("hello");
s.push_front("world");
```

遍历：

```cpp
for (list<string>::iterator p = s.begin(); p != s.end(); ++p) {
    cout << *p << " ";
}
```

注意：链表迭代器不能用 `p < s.end()`，因为链表节点不连续，没有大小比较意义。

### 11.6 map

`map` 存 key-value：

```cpp
#include <map>
#include <string>

map<string, float> price;
price["snapple"] = 0.75;
```

`map` 用 key 查找 value：

```cpp
cout << price["snapple"];
```

但注意陷阱：

```cpp
if (foo["bob"] == 1) {}
```

如果 `"bob"` 不存在，`operator[]` 会创建一个新条目。只检查是否存在时用：

```cpp
if (foo.count("bob") != 0) {}
```

### 11.7 algorithms

STL 算法接受迭代器作为参数：

```cpp
find(v.begin(), v.end(), 3);
sort(v.begin(), v.end());
copy(L.begin(), L.end(), back_inserter(V));
```

算法不需要知道容器内部结构，只通过迭代器工作。

### 11.8 typedef/using/auto

长类型名很烦：

```cpp
map<Name, list<PhoneNum>>::iterator finger;
```

可以：

```cpp
typedef map<Name, list<PhoneNum>> PhoneBook;
PhoneBook::iterator finger;
```

现代 C++：

```cpp
using PhoneBook = map<Name, list<PhoneNum>>;
auto finger = phonebook.begin();
```

### 11.9 自定义类用于 STL

可能需要：

- 默认构造函数。
- 拷贝构造函数。
- 赋值运算符。
- 比较运算符，尤其是 `set`、`map` 等排序容器。

排序容器需要知道两个对象谁小：

```cpp
bool operator<(const FullName& a, const FullName& b);
```

### 11.10 STL 常见陷阱

PPT 列出：

- 越界访问 vector：

```cpp
vector<int> v;
v[100] = 1; // wrong
```

- 用 `map::operator[]` 无意插入。
- 对 `list` 用低效或不合适操作。
- 使用失效迭代器。例如容器修改后，原迭代器可能失效。

## 12. 第 12 讲 Iterators

底稿：[第 12 讲逐页底稿](pagewise/12_12_Iterators_pagewise.md)

### 12.1 迭代器是什么

PPT 定义：迭代器提供一种顺序访问聚合对象元素的方法，而不暴露底层表示。它是指针的泛化。

作用：

- 访问容器元素。
- 统一算法接口。
- 分离容器和算法。

```cpp
template <class InputIterator, class T>
InputIterator find(InputIterator first, InputIterator last, const T& value);
```

### 12.2 begin/end 思想

```cpp
if (find(vec.begin(), vec.end(), 3) == vec.end()) {
    cout << "3 not found";
}
```

区间 `[begin, end)`：

- `begin()` 指向第一个元素。
- `end()` 指向最后一个元素后面的位置，不是有效元素。
- 遍历条件通常是 `it != end()`。

### 12.3 迭代器像指针

迭代器通常支持：

- `++it`：移动到下一个元素。
- `*it`：访问当前元素。
- `it->member`：访问元素成员。

不同容器迭代器能力不同，不能假设所有迭代器都支持 `+`、`-`、`<`。

### 12.4 自定义链表迭代器

PPT 用 `List`、`ListItem`、`ListIter` 展示：

```cpp
template <class T>
class ListItem {
public:
    T& val() { return _value; }
    ListItem* next() { return _next; }
private:
    T _value;
    ListItem* _next;
};
```

迭代器内部保存节点指针，通过 `operator*` 和 `operator++` 模拟指针行为。

### 12.5 associated type

算法有时需要知道迭代器指向的值类型。例如：

```cpp
typename I::value_type
```

容器迭代器可以在内部 typedef：

```cpp
template <class T>
struct myIter {
    typedef T value_type;
};
```

但问题是原生指针 `int*` 没有 `value_type`。

### 12.6 iterator_traits

为支持普通迭代器和原生指针，STL 使用 traits：

```cpp
template <class I>
struct iterator_traits {
    typedef typename I::value_type value_type;
};

template <class T>
struct iterator_traits<T*> {
    typedef T value_type;
};

template <class T>
struct iterator_traits<const T*> {
    typedef T value_type;
};
```

这样算法可以统一写：

```cpp
typename iterator_traits<I>::value_type
```

### 12.7 模板特化

PPT 讲了 primary template 和 explicit specialization。

```cpp
template<class T1, class T2, int I>
class A { };

template<>
class A<int, double, 5> { };
```

特化允许你为某些类型组合写特殊版本。

### 12.8 迭代器类别

PPT 列出：

- InputIterator：只读输入，单向。
- OutputIterator：只写输出，单向。
- ForwardIterator：可多次遍历，单向。
- BidirectionalIterator：可前进后退。
- RandomAccessIterator：随机访问，支持 `+ n`、`- n`、比较。

关系大致是能力逐渐增强。

### 12.9 advance 的优化

不同迭代器移动 n 步的最佳方式不同：

- InputIterator：只能循环 `++`。
- BidirectionalIterator：n 正向 `++`，n 负向 `--`。
- RandomAccessIterator：直接 `it += n`。

STL 利用 iterator category tag 和 traits 选择实现：

```cpp
advance(it, n);
```

这就是 generic programming 的精妙点：统一接口，内部根据类型能力优化。

### 12.10 distance

`distance(first, last)` 计算两个迭代器距离：

- 对 input/bidirectional 可能需要循环。
- 对 random access 可直接 `last - first`。

### 12.11 总结

PPT 最后总结：

- Container knows how to design its own iterator。
- Traits trick extracts type information embedded in different iterators, including raw pointers。
- Algorithms are independent to containers。

## 13. 第 13 讲 Exceptions

底稿：[第 13 讲逐页底稿](pagewise/13_13_Exceptions_pagewise.md)

### 13.1 为什么需要异常

C++ 哲学是 badly formed code will not be run，但运行时仍会出错：

- 文件打不开。
- 内存分配失败。
- 下标越界。
- 网络断开。
- 输入格式错误。

传统错误码会把正常逻辑和错误处理混在一起。异常可以把“做什么”和“出错怎么办”分离。

### 13.2 用错误码读文件的问题

PPT 对比了：

```text
open file
determine size
allocate memory
read file
close file
```

每一步都可能失败。如果用错误码，代码会充满嵌套判断。

异常写法：

```cpp
try {
    openFile();
    determineSize();
    allocateMemory();
    readFile();
} catch (...) {
    handleError();
}
```

### 13.3 Vector 下标越界例子

```cpp
template <class T>
T& Vector<T>::operator[](int idx)
{
    if (idx < 0 || idx >= m_size) {
        // what should we do?
    }
    return m_elements[idx];
}
```

选择：

- 返回特殊错误值：对泛型 `T` 不可靠。
- 直接 `exit(22)`：库代码不应该擅自终止整个程序。
- 抛异常：让调用者决定怎么处理。

### 13.4 throw

```cpp
class VectorIndexError {
public:
    VectorIndexError(int index) : m_index(index) {}
private:
    int m_index;
};

throw VectorIndexError(idx);
```

可以抛任何对象，但最好抛能表达错误信息的类型。

### 13.5 try/catch

```cpp
try {
    v[i] = 10;
} catch (const VectorIndexError& e) {
    // handle
}
```

如果调用者不关心，可不 catch，异常会继续向调用栈上传播，直到找到匹配 handler。

### 13.6 handler 选择

PPT 说 handler 按出现顺序检查：

1. 精确匹配。
2. 可接受转换或基类匹配。
3. `catch(...)` 捕获所有。

更具体的异常类型应放在更前面，基类异常放后面。

### 13.7 继承异常层次

可以定义异常基类：

```cpp
class MathErr {};
class UnderFlowErr : public MathErr {};
class ZeroDivideErr : public MathErr {};
```

然后：

```cpp
catch (const UnderFlowErr& e) {}
catch (const MathErr& e) {}
```

### 13.8 标准库异常

PPT 提到 `new` 失败不会返回 0，而是抛出 `bad_alloc`：

```cpp
try {
    int* p = new int[huge];
} catch (const std::bad_alloc& e) {
}
```

标准异常通常来自 `<exception>`、`<stdexcept>`，如：

- `std::exception`
- `std::runtime_error`
- `std::logic_error`
- `std::out_of_range`
- `std::bad_alloc`

### 13.9 noexcept

异常规格说明函数是否可能抛异常。现代 C++ 常用：

```cpp
void abc(int a) noexcept;
```

`noexcept` 是接口承诺。如果 `noexcept` 函数抛出异常，会调用 `std::terminate`。

### 13.10 什么时候用异常

课件建议：

- 异常应表示错误。
- 不要用异常代替正常控制结构。
- 如果局部 `if` 能处理，就不要用异常。
- 库代码不要擅自终止程序，应该抛异常让调用者决定。

### 13.11 RAII 与异常

PPT 强调用对象 acquire/release resources：

```cpp
void func() {
    File f("some file");
    // if exception occurs, f destructor still closes file
}
```

RAII 是 Resource Acquisition Is Initialization。资源交给对象管理，对象析构时释放。异常发生时，栈展开会调用已构造对象的析构函数。

### 13.12 构造函数中的异常

构造函数不能返回错误码。可选设计：

- 抛异常。
- 使用 uninitialized flag。
- 把可能失败的工作延迟到 `init()`。

如果构造函数抛异常：

- 该对象的析构函数不会被调用，因为对象没构造完成。
- 已经构造完成的成员对象会被析构。
- 构造函数中手动申请的裸资源要小心泄漏，最好用智能指针或成员对象管理。

### 13.13 析构函数中的异常

析构函数在正常离开作用域和异常栈展开时都会被调用。如果析构函数在栈展开期间再抛异常，会调用 `std::terminate()`。

经验规则：析构函数不要抛异常。

### 13.14 捕获异常的方式

PPT 建议 catch by reference：

```cpp
catch (const std::exception& e)
```

原因：

- catch by value 会 slicing。
- catch by pointer 会增加普通代码和异常处理代码的耦合。

### 13.15 异常安全

BankAccount 例子说明：

```cpp
reduceBalance(amount);
prepareCash(); // throws
releaseCash();
```

如果余额已减少，准备现金失败，账户状态就不一致。异常安全代码要保证：

- 基本保证：对象仍有效，不泄漏资源。
- 强保证：操作失败时状态回滚到调用前。
- 不抛保证：操作保证不抛。

### 13.16 wrap-up

课件总结：

- 早期设计错误处理策略。
- 不要过度使用 try/catch。
- 不要用异常替代局部控制结构。
- 并非每个函数都能处理每个错误。
- 重要接口可使用异常规格。
- 库代码不应决定终止程序。
- 未捕获异常会调用 `std::terminate()`，也可设置 terminate handler。

## 14. 第 14 讲 Smart Pointers

底稿：[第 14 讲逐页底稿](pagewise/14_14_Smart_Pointers_pagewise.md)

### 14.1 智能指针的目标

课件先提到标准库智能指针：

- `std::unique_ptr`
- `std::shared_ptr`

智能指针把裸指针包装成栈上对象，通过构造/析构自动管理堆资源。

### 14.2 引用计数

Reference count 是记录某个共享对象被多少指针引用。

规则：

- 每个 shareable object 有一个 counter。
- 初始值通常为 0 或 1，取决于设计。
- 指针赋值或拷贝时计数增加。
- 指针离开或改指向时计数减少。
- 计数为 0 时释放对象。

### 14.3 copy-on-write 图示

PPT 用 String：

```cpp
String x("abcdef");
String y = x; // shallow copy of x
x = "Hello world"; // copy on write
```

含义：

- 一开始 x 和 y 可共享同一份字符串表示。
- 如果其中一个要修改，就复制一份，避免影响另一个。

现代 C++ 标准库 `std::string` 不鼓励依赖 COW，但这个例子用于理解引用计数。

### 14.4 UCObject

课件设计了一个侵入式引用计数基类：

```cpp
class UCObject {
public:
    UCObject();
    void incr();
    void decr();
private:
    int m_refCount;
};
```

`decr()` 中如果计数为 0，就 `delete this`。

### 14.5 UCPointer

模板智能指针：

```cpp
template <class T>
class UCPointer {
private:
    T* m_pObj;
public:
    UCPointer(T* p);
    UCPointer(const UCPointer& p);
    ~UCPointer();
    UCPointer& operator=(const UCPointer& p);
    T* operator->() const;
    T& operator*() const;
};
```

拷贝构造增加计数：

```cpp
template <class T>
UCPointer<T>::UCPointer(const UCPointer<T>& p)
{
    m_pObj = p.m_pObj;
    if (m_pObj) m_pObj->incr();
}
```

赋值要先增加新对象计数，再减少旧对象计数，避免自赋值或同对象问题。

### 14.6 Envelope and Letter

PPT 用 Envelope/Letter 模式：

- String 是 envelope，提供干净接口。
- StringRep 是 letter，保存实际字符串数据。
- UCPointer 管理引用计数。
- UCObject 隐藏计数细节。

### 14.7 StringRep

```cpp
class StringRep : public UCObject {
public:
    StringRep(const char*);
    ~StringRep();
    StringRep(const StringRep&);
    int length() const { return strlen(m_pChars); }
    int equal(const StringRep&) const;
private:
    char* m_pChars;
};
```

构造时分配字符数组，析构时 `delete[]`。

### 14.8 String

```cpp
class String {
private:
    UCPointer<StringRep> m_rep;
public:
    String(const char* s) : m_rep(new StringRep(s)) {}
    String(const String& s) : m_rep(s.m_rep) {}
    String& operator=(const String& s) {
        m_rep = s.m_rep;
        return *this;
    }
};
```

String 自己的构造、拷贝和赋值很干净，因为资源管理交给 `UCPointer`。

### 14.9 评价

PPT critique：

- UCPointer 维护引用计数。
- UCObject 隐藏计数细节。
- String 很干净。
- StringRep 只负责字符串存储和操作。
- UCObject 和 UCPointer 可复用。
- 比裸指针慢。
- 设计是 invasive 的，因为被管理对象必须继承 UCObject。
- `std::shared_ptr` 是非侵入式设计。

### 14.10 现代智能指针

虽然 PPT 主要讲手写引用计数，但现代 C++ 实践：

```cpp
std::unique_ptr<T> p = std::make_unique<T>();
std::shared_ptr<T> q = std::make_shared<T>();
std::weak_ptr<T> w = q;
```

- `unique_ptr`：独占所有权，不能拷贝，只能移动。
- `shared_ptr`：共享所有权，引用计数。
- `weak_ptr`：观察 shared 对象，不增加引用计数，可打破循环引用。

## 15. 第 15 讲 Miscellaneous Points

底稿：[第 15 讲逐页底稿](pagewise/15_15_Miscellaneous_Points_pagewise.md)

### 15.1 named casts

C 风格转换：

```cpp
(double*) &a
```

危险，因为它可以做多种逻辑不同的转换，读代码的人不知道意图。

C++ 提供命名转换：

- `static_cast`
- `dynamic_cast`
- `const_cast`
- `reinterpret_cast`

### 15.2 static_cast

用于相对正常、编译期可检查的转换：

```cpp
double d = 7.1;
int a = static_cast<int>(d);
```

也可用于有继承关系的上/下行转换，但下行转换不做运行时安全检查。

### 15.3 dynamic_cast

用于多态类型的安全下行转换：

```cpp
struct A { virtual void f() {} };
struct B : A {};

A* p = new B;
B* q = dynamic_cast<B*>(p);
```

要求基类有虚函数。若转换失败：

- 指针转换返回 `nullptr`。
- 引用转换抛 `std::bad_cast`。

### 15.4 const_cast

用于移除或添加 const：

```cpp
const int c = 7;
int* q = const_cast<int*>(&c);
```

移除 const 后修改真正的 const 对象是未定义行为。只能在你非常确定原对象本来不是 const 时使用。

### 15.5 reinterpret_cast

用于低层位模式解释，例如把 `int*` 强行当 `double*`。PPT 示例：

```cpp
int a = 7;
double* p = reinterpret_cast<double*>(&a);
```

这通常非常危险，因为 `a` 并不是 double。除系统底层代码外应尽量避免。

### 15.6 多重继承

一个类继承多个基类：

```cpp
class Consultant : public MTS, public Temporary {};
```

问题：

- 数据布局复杂。
- 同名成员冲突。
- 基类重复。
- 构造顺序复杂。
- 代码在 virtual bases 中可能被调用多次。
- 有运行时和空间开销。

PPT 的建议非常直接：TIPS for MI: In general, SAY NO。

### 15.7 多重继承的安全用途

比较安全的场景是 protocol/interface classes。也就是只定义接口的抽象基类。

例如 Unix character device：

```cpp
class CDevice {
public:
    virtual ~CDevice() {}
    virtual int open() = 0;
    virtual int close() = 0;
};
```

实现类可以同时实现多个接口。

### 15.8 重复基类和虚基类

钻石继承：

```cpp
struct B1 { int m_i; };
struct D1 : public B1 {};
struct D2 : public B1 {};
struct MI : public D1, public D2 {};
```

`MI` 中会有两份 `B1`。如果想共享一份基类，用 virtual base：

```cpp
struct D1 : virtual public B1 {};
struct D2 : virtual public B1 {};
```

PPT 提醒：virtual base 有运行时和空间开销。如果重复基类不是问题，就不要为了形式上“共享”而使用。

### 15.9 命名空间为什么需要

全局作用域中名字容易冲突：

```cpp
// old1.h
void f();

// old2.h
void f();
```

命名空间提供逻辑分组：

```cpp
namespace MyLib {
    void foo();
    class Cat {};
}
```

命名空间也是作用域，像类一样管理名字。

### 15.10 定义和实现命名空间

头文件：

```cpp
namespace MyLib {
    void foo();
    class Cat {
    public:
        void Meow();
    };
}
```

源文件：

```cpp
#include "MyLib.h"

void MyLib::foo()
{
    cout << "foo\n";
}

void MyLib::Cat::Meow()
{
    cout << "meow\n";
}
```

### 15.11 使用命名空间名字

完整限定：

```cpp
MyLib::foo();
MyLib::Cat c;
c.Meow();
```

using-declaration：

```cpp
using MyLib::foo;
using MyLib::Cat;
foo();
Cat c;
```

using-directive：

```cpp
using namespace MyLib;
```

课件提醒：using-directive 可能制造歧义。

### 15.12 歧义

```cpp
namespace XLib { void y(); }
namespace YLib { void y(); }

using namespace XLib;
using namespace YLib;

y();       // ambiguous
XLib::y(); // OK
```

using-directive 只是让名字可见，真正调用时才出现歧义。用作用域限定解决。

### 15.13 namespace alias

长命名空间可取别名：

```cpp
namespace supercalifragilistic {
    void f();
}

namespace short_ns = supercalifragilistic;
short_ns::f();
```

也常用于库版本管理。

### 15.14 namespace composition

可以组合命名空间：

```cpp
namespace mine {
    using namespace first;
    using namespace second;
    using first::y; // resolve clashes
    void mystuff();
}
```

也可以只选择部分名字：

```cpp
namespace mine {
    using orig::Cat;
    void x();
    void y();
}
```

### 15.15 namespaces are open

同一个命名空间可以在多个文件中继续添加声明：

```cpp
namespace X {
    void f();
}

namespace X {
    void g();
}
```

最终 `X` 同时有 `f` 和 `g`。

## 17. 初学者最容易错的点

1. 定义指针不等于创建对象。
2. `new[]` 必须配 `delete[]`。
3. 引用必须初始化，不能换绑。
4. `const string*` 和 `string* const` 不一样。
5. 构造函数没有返回类型。
6. 初始化列表不是语法装饰，很多场景必须使用。
7. 头文件放声明，普通函数定义不要随便放头文件。
8. 类内定义的成员函数自动 inline。
9. public 继承才表达普通 is-a。
10. 通过基类指针删除派生类对象时，基类析构函数必须 virtual。
11. 多态对象不要按值传递，否则可能 slicing。
12. 有裸指针资源时，默认拷贝通常危险。
13. `a = b` 是赋值，`T a = b` 是初始化。
14. 后置 `x++` 比前置 `++x` 通常更贵，因为要保存旧值。
15. `operator[]` 返回引用才能作为左值。
16. `map[key]` 会在 key 不存在时插入。
17. `list` 迭代器不能用 `<` 比较。
18. 模板参数推导不自动做普通类型转换。
19. catch 异常应优先用 `const T&`。
20. 析构函数不要抛异常。
21. `shared_ptr` 可能循环引用，需要 `weak_ptr`。
22. `using namespace` 方便但可能造成名字冲突。
23. C 风格 cast 信息太少，优先使用 named casts。
24. 多重继承通常不必要，接口类是相对安全的用途。

## 20. 期末考试常见题型与答题方法

### 20.1 概念解释题

常见问法：

- 什么是 encapsulation / abstraction / inheritance / polymorphism？
- 指针和引用有什么区别？
- constructor 和 destructor 的作用是什么？
- virtual function 如何实现 dynamic binding？
- copy constructor 和 assignment operator 有什么区别？
- STL 的 containers、algorithms、iterators 各自作用是什么？

答题模板：

1. 先给定义。
2. 再说明解决什么问题。
3. 再给 C++ 语法或例子。
4. 最后指出易错点或限制。

例：解释多态。

标准答法：

多态是指同一个接口在运行时根据对象真实类型表现出不同行为。在 C++ 中，通常通过基类指针或引用调用虚函数实现。基类函数声明为 `virtual`，派生类 override 后，通过 `Base*` 或 `Base&` 调用时会发生动态绑定。它解决的问题是：调用者只依赖抽象接口，不需要知道具体派生类。易错点是：按值传递会发生 slicing；基类析构函数如果要通过基类指针删除派生对象，应声明为 virtual。

### 20.2 代码输出题

答题步骤：

1. 找对象创建位置，写出构造函数调用顺序。
2. 找作用域结束位置，写出析构函数调用顺序。
3. 看函数是否 virtual，决定静态绑定还是动态绑定。
4. 看传参方式：按值、引用、指针、const 引用。
5. 看是否发生拷贝构造或赋值。
6. 看是否发生隐式类型转换或运算符重载。

构造析构题尤其要记：

```text
派生类构造：先基类，再成员对象，再派生类自身。
派生类析构：先派生类自身，再成员对象，再基类。
同一类中成员对象的初始化顺序由声明顺序决定，不由初始化列表书写顺序决定。
```

### 20.3 改错题

常见错误：

```cpp
int* p = new int[10];
delete p;      // 错，应为 delete[] p
```

```cpp
class X {
    const int n;
public:
    X(int x) { n = x; } // 错，const 成员必须初始化列表初始化
};
```

```cpp
Base* p = new Derived;
delete p; // 若 Base 析构不是 virtual，危险
```

```cpp
Person a("Tom");
Person b = a; // 如果 Person 内部有 char* 且未写深拷贝，可能 double delete
```

改错题答题不要只写“错”，要说明为什么错，以及正确写法。

### 20.4 设计题

常见问法：

- 给一个场景，让你判断用组合还是继承。
- 给多个类型，让你设计基类和派生类。
- 给资源管理类，让你写构造、析构、拷贝构造、赋值。
- 给容器使用场景，让你选择 `vector`、`list`、`map`。

答题原则：

- has-a 用组合。
- is-a 且满足替换原则，用 public 继承。
- 需要运行时多态，用 virtual 和基类指针/引用。
- 管理资源，优先 RAII；如果必须裸指针，要写 Rule of Three。
- 随机访问多，用 `vector`；频繁中间插入删除且已有位置迭代器，用 `list`；键值查找，用 `map`。

## 21. 第 1-3 讲增强考点：从 C++ 入门到类

### 21.1 C++ 为什么不是“带 class 的 C”

考试可能会问：C++ 和 C 的关系是什么？

答法：

C++ 建立在 C 之上，保留了 C 的效率、指针、内存模型和底层控制能力，但它不是简单的 C 扩展。C++ 增加了数据抽象、访问控制、构造析构、函数重载、运算符重载、继承、多态、模板、异常和标准库。C++ 支持多种编程范式：过程式、面向对象、泛型等。用 C++ 写程序时，应尽量让对象管理资源，而不是到处手写裸指针和手动释放。

### 21.2 `#include`、声明、定义、链接

可能考点：

- `#include` 做了什么？
- 为什么头文件不要放普通函数定义？
- declaration 和 definition 区别？
- 编译单元是什么？

关键理解：

`#include` 是预处理阶段的文本插入。编译器每次编译一个 `.cpp` 文件，这个 `.cpp` 加上它 include 进来的内容形成一个 translation unit。编译后生成目标文件，最后由 linker 链接。

声明告诉编译器“有这个名字、类型长这样”：

```cpp
int f(int);
extern int g;
```

定义真正分配实体或给出函数体：

```cpp
int g = 0;
int f(int x) { return x + 1; }
```

如果普通函数定义放头文件，被多个 `.cpp` include，就可能出现 multiple definition。例外是 `inline` 函数和模板，因为它们需要在使用处可见并允许多处一致定义。

### 21.3 头文件保护为什么必要

```cpp
#ifndef POINT_H
#define POINT_H

class Point {};

#endif
```

它防止同一个头文件在一个编译单元中被重复包含。考试中若看到类重复定义错误，要想到 include guard 或 `#pragma once`。

### 21.4 class 与 struct 的默认访问权限

```cpp
class A {
    int x; // 默认 private
};

struct B {
    int x; // 默认 public
};
```

除此之外，`class` 和 `struct` 都可以有构造函数、成员函数、继承、模板等。不要误以为 struct 不能有函数。

### 21.5 `this` 的考试理解

成员函数：

```cpp
void Point::move(int dx, int dy) {
    x += dx;
    y += dy;
}
```

可以理解成隐藏地带着一个 `this` 指针：

```cpp
void Point_move(Point* this, int dx, int dy) {
    this->x += dx;
    this->y += dy;
}
```

但真实语法中不能显式声明 `this`。`this` 只存在于非 static 成员函数中。static 成员函数没有 `this`，所以不能直接访问普通成员。

### 21.6 对象、类、字段、局部变量

可能考题：字段、参数、局部变量生命周期有什么不同？

答法：

- 字段是对象的一部分，随对象创建和销毁。
- 参数在函数调用时创建，函数结束销毁。
- 局部变量在其作用域内存在，离开作用域销毁。
- static 局部变量作用域仍在函数内，但生命周期贯穿整个程序。

### 21.7 从 TicketMachine 看对象建模

PPT 中 TicketMachine 的图示实际是在训练你做类设计：

```cpp
class TicketMachine {
private:
    int price;
    int balance;
    int total;
public:
    TicketMachine(int ticketCost);
    int getPrice() const;
    int getBalance() const;
    void insertMoney(int amount);
    void printTicket();
    int refundBalance();
};
```

考试中如果给“售票机、银行账户、学生成绩系统”这类场景，要先识别：

- 哪些是对象状态，放 private 字段。
- 哪些是对象行为，放 public 成员函数。
- 哪些内部细节不应暴露。

## 22. 第 2 讲增强考点：内存、指针、引用、const

### 22.1 `std::string` 相对 C 字符串的优势

可能考题：为什么 C++ 里推荐 `std::string`？

答法：

`std::string` 是标准库类，自动管理字符内存，支持赋值、拼接、比较、查找、子串等操作。C 字符串是以 `'\0'` 结尾的字符数组，程序员必须自己保证空间足够和结尾正确，容易越界和内存错误。

注意：

```cpp
char cstr[20] = "jaguar";
string s = "jaguar";
```

`cstr` 是数组，大小固定；`s` 是对象，会管理内部动态存储。

### 22.2 内存区域与生命周期

考试中常要求判断变量在哪里：

```cpp
int g;                 // 全局/静态区
static int sg;          // 全局/静态区，文件内可见

void f() {
    int x;              // 栈
    static int sx;      // 静态区，函数内可见
    int* p = new int;   // p 在栈，*p 在堆
}
```

要区分“指针变量本身”和“指针指向的对象”。这是内存题最常见陷阱。

### 22.3 `extern` 与文件级 `static`

```cpp
// a.cpp
int global_value = 10;
static int hidden_value = 20;

// b.cpp
extern int global_value; // OK
extern int hidden_value; // 链接失败，hidden_value 只在 a.cpp 内可见
```

`extern` 是声明，不分配新变量；文件级 `static` 限制外部链接性。

### 22.4 `new/delete` 动画页的真正考点

PPT 中第 2 讲有很多 new-delete 机制的连续图，核心不是记图，而是理解状态变化：

```cpp
int* p = new int;
int* a = new int[10];
Student* q = new Student();
```

执行后：

- `p` 保存一个堆上 `int` 的地址。
- `a` 保存数组第一个元素地址。
- `q` 指向堆上 Student 对象，并且构造函数已调用。

释放：

```cpp
delete p;     // 释放单个 int
delete[] a;   // 释放数组
delete q;     // 调用 Student 析构并释放内存
```

常考错误：

```cpp
int* p = new int[10];
delete p; // 错，应为 delete[] p
```

```cpp
int x;
delete &x; // 错，x 不是 new 出来的
```

```cpp
delete p;
delete p; // 错，重复释放
```

### 22.5 引用的本质和限制

引用是别名，不是可重新绑定的指针。

```cpp
int x = 1;
int y = 2;
int& r = x;
r = y; // 不是让 r 引用 y，而是把 y 的值赋给 x
```

考试常考判断：

```cpp
int& r;       // 错，引用必须初始化
int&* p;      // 错，不能有指向引用的指针
int&& rr = 3; // 这是右值引用，PPT 未重点讲，期末一般不考
```

### 22.6 `const` 指针四种写法

必须能快速判断：

```cpp
const int* p;        // p 指向的 int 不能通过 p 修改；p 可改指向
int const* p;        // 同上
int* const p = &x;   // p 不能改指向；可通过 p 修改 x
const int* const p = &x; // 指向和指向内容都不能通过 p 改
```

口诀：从右往左读，`*` 表示 pointer to，`const` 修饰它旁边的东西。

### 22.7 传参方式的考试判断

```cpp
void f1(Person p);             // 拷贝，可能调用 copy constructor
void f2(Person* p);            // 传地址，可能为空，可修改对象
void f3(Person& p);            // 传引用，不能为空，可修改对象
void f4(const Person& p);      // 不拷贝，不可修改，推荐大对象只读传参
```

常见题：为什么 `const T&` 适合大对象？

答：避免按值拷贝的开销，同时通过 const 防止函数修改实参。

## 23. 第 4 讲增强考点：构造、析构、初始化、inline

### 23.1 构造函数不是普通函数

构造函数特点：

- 与类同名。
- 无返回类型，连 `void` 也不能写。
- 创建对象时自动调用。
- 可重载。
- 主要职责是建立对象不变量。

错误写法：

```cpp
class X {
public:
    void X(); // 错，这只是一个普通成员函数且非法风格，不是构造函数
};
```

### 23.2 默认构造函数的生成规则

如果你没有声明任何构造函数，编译器会隐式生成默认构造函数。

```cpp
class A {
    int x;
}; // A::A() 隐式存在
```

但只要你声明了任意构造函数，编译器不再自动生成无参构造：

```cpp
class B {
public:
    B(int);
};

B b; // 错，没有 B()
```

### 23.3 初始化列表必考场景

必须用初始化列表：

```cpp
class X {
    const int c;
    int& r;
    Member m;
public:
    X(int value, int& ref) : c(value), r(ref), m(value) {}
};
```

原因：

- `const` 成员只能初始化，不能先默认构造再赋值。
- 引用必须绑定。
- 没有默认构造函数的成员对象必须显式构造。
- 基类部分必须在派生类构造函数体之前构造。

### 23.4 初始化顺序陷阱

```cpp
class X {
    int a;
    int b;
public:
    X() : b(1), a(b + 1) {}
};
```

虽然初始化列表写 `b` 在前，但真正初始化顺序由成员声明顺序决定：先 `a`，后 `b`。所以 `a(b + 1)` 中的 `b` 还未初始化。考试中看到这种题，要看类里字段声明顺序。

### 23.5 析构函数和作用域

```cpp
void f() {
    X a;
    {
        X b;
    } // b 析构
}     // a 析构
```

析构函数自动调用。若对象是动态分配的：

```cpp
X* p = new X;
delete p; // 析构函数在 delete 时调用
```

如果忘记 `delete`，析构函数不会及时调用，资源泄漏。

### 23.6 函数重载和默认参数的冲突

```cpp
void f(int);
void f(double);
f('a');
```

需要判断最佳匹配。字符可提升到 int，也可转换到 double，一般 int 更好。

默认参数必须从右到左：

```cpp
int ok(int a, int b = 0, int c = 0);
int bad(int a = 0, int b); // 错
```

默认参数通常写在声明处，不要在声明和定义处重复写两遍。

### 23.7 const 成员函数重载

```cpp
class A {
public:
    int get() const;
    void set(int);
};

const A a;
a.get(); // OK
a.set(1); // 错
```

`const` 对象只能调用 const 成员函数。非 const 对象可以调用 const 和非 const 成员函数。

### 23.8 inline 的真正含义

PPT 说 inline 原意是消除函数调用开销，但现代 C++ 中 `inline` 更重要的含义是允许多个 translation unit 中有同一函数定义，只要定义完全相同。

考试答法：

- 小而频繁调用的函数适合 inline。
- inline 定义通常放头文件。
- 编译器可以不真正内联。
- 宏不是 inline 的替代，因为宏没有类型检查，可能重复求值。

## 24. 第 5-6 讲增强考点：组合、继承、多态

### 24.1 has-a 和 is-a 判断

考试经常给类关系让你判断：

- `Car` has an `Engine`：组合。
- `Manager` is an `Employee`：继承。
- `Circle` is a `Shape`：继承。
- `Student` has a `Name`：组合。

如果只是“拥有/包含/由什么组成”，用组合。如果是“可以当作某种更一般类型使用”，用 public 继承。

### 24.2 为什么嵌入对象通常 private

```cpp
class Employee {
private:
    Name name;
    Address address;
};
```

原因：

1. `Name` 和 `Address` 是实现细节。
2. 外部不应依赖内部组成。
3. 将来可以改变内部表示，不影响 public 接口。

### 24.3 DoME 类图的考试含义

PPT 中 DoME 的 CD/DVD 示例是继承设计题模板。

错误设计：

```cpp
class CD {
    string title;
    int playingTime;
    bool gotIt;
    string comment;
    string artist;
};

class DVD {
    string title;
    int playingTime;
    bool gotIt;
    string comment;
    string director;
};
```

问题：公共字段和公共方法重复。

改进：

```cpp
class Item {
protected:
    string title;
    int playingTime;
    bool gotIt;
    string comment;
public:
    virtual void print() const;
};

class CD : public Item {
    string artist;
    int numberOfTracks;
};

class DVD : public Item {
    string director;
};
```

如果需要把 CD、DVD 放入同一个 collection，并按真实类型调用 `print`，则 `print` 应为 virtual。

### 24.4 public/protected/private 访问和继承

成员访问：

| 成员权限 | 类内 | 派生类 | 外部客户 |
|---|---|---|---|
| public | 可访问 | 可访问 | 可访问 |
| protected | 可访问 | 可访问 | 不可访问 |
| private | 可访问 | 不可直接访问 | 不可访问 |

public 继承后：

- 基类 public 仍 public。
- 基类 protected 仍 protected。
- 基类 private 仍不可直接访问。

private 继承后：

- 基类 public/protected 都变成派生类 private。
- 不表达普通 is-a。

### 24.5 upcasting 与替换原则

```cpp
Manager m(...);
Employee* ep = &m;
Employee& er = m;
```

这是 upcasting。它安全，因为 Manager 是 Employee。

但通过 `Employee*` 只能访问 Employee 接口：

```cpp
ep->get_name(); // OK
ep->get_title(); // 错，静态类型是 Employee*
```

如果调用的是 virtual 函数，运行时会按真实对象类型分派。

### 24.6 virtual 的核心考点

```cpp
class Shape {
public:
    virtual void render();
};

class Circle : public Shape {
public:
    void render() override;
};

Shape* p = new Circle;
p->render(); // 调 Circle::render
```

如果没有 virtual：

```cpp
class Shape {
public:
    void render();
};
```

则 `p->render()` 由指针静态类型决定，调用 `Shape::render`。

### 24.7 vptr/vtable 图如何答

简答题可能问 virtual 如何实现。

答法：

含虚函数的类对象通常包含隐藏的 vptr。vptr 指向该类对应的 vtable。vtable 保存虚函数地址。通过基类指针或引用调用虚函数时，程序通过对象中的 vptr 找到真实类型的 vtable，再跳转到对应函数。因此 virtual 带来运行时开销和对象空间开销，但换来动态绑定。

不要说“C++ 标准规定一定这样实现”。更严谨说法是“主流实现通常如此”。

### 24.8 slicing 必考

```cpp
void f(Shape s); // 按值传参

Circle c;
f(c); // slicing
```

按值传递时只复制基类部分，派生类特有部分被切掉。解决：

```cpp
void f(const Shape& s);
void f(Shape* s);
```

### 24.9 虚析构必考

```cpp
class Base {
public:
    ~Base() {}
};

class Derived : public Base {
    int* p;
public:
    ~Derived() { delete p; }
};

Base* b = new Derived;
delete b; // 若 Base 析构非 virtual，Derived 析构可能不执行
```

正确：

```cpp
class Base {
public:
    virtual ~Base() {}
};
```

只要类打算作为多态基类使用，析构函数就应为 virtual。

### 24.10 纯虚函数和抽象类

```cpp
class Device {
public:
    virtual ~Device() {}
    virtual void open() = 0;
    virtual void close() = 0;
};
```

含纯虚函数的类是抽象类，不能直接实例化。它用于定义接口并强制派生类实现。

## 25. 第 7-8 讲增强考点：拷贝控制、static、运算符重载

### 25.1 拷贝构造什么时候调用

```cpp
Person a("Tom");
Person b = a;      // 拷贝构造
Person c(a);       // 拷贝构造
f(a);              // 如果 f(Person p)，拷贝构造
return a;          // 可能拷贝构造，也可能被优化
```

不调用拷贝构造的情况：

```cpp
Person a("Tom");
Person b("Jerry");
b = a; // 赋值运算符，不是拷贝构造
```

### 25.2 拷贝构造签名为什么是 `const T&`

```cpp
T::T(const T& other);
```

原因：

- 用引用避免为了传参又复制一次，导致无限递归。
- 用 const 允许从 const 对象和临时对象拷贝。

错误：

```cpp
T::T(T other); // 错，传参本身需要拷贝构造
```

### 25.3 深浅拷贝图像页的考试语言

浅拷贝：

```cpp
Person a("Tom");
Person b = a;
```

如果只是复制 `char* name` 的地址，则 `a.name` 和 `b.name` 指向同一块堆内存。问题：

- 一个对象修改名字会影响另一个。
- 两个对象析构时会 delete 同一地址，double delete。

深拷贝：

```cpp
Person::Person(const Person& other) {
    name = new char[strlen(other.name) + 1];
    strcpy(name, other.name);
}
```

每个对象拥有自己的字符数组。

### 25.4 Rule of Three

如果一个类需要自定义以下任意一个，通常三个都要考虑：

1. 析构函数。
2. 拷贝构造函数。
3. 拷贝赋值运算符。

原因：三者都和资源所有权有关。只写析构不写拷贝，会导致默认浅拷贝；只写拷贝构造不写赋值，会导致赋值时浅拷贝。

现代 C++ 扩展为 Rule of Five，还包括移动构造和移动赋值，但 PPT 主要覆盖 Rule of Three。

### 25.5 赋值运算符标准骨架

```cpp
T& T::operator=(const T& rhs) {
    if (this != &rhs) {
        // 1. 释放旧资源
        // 2. 分配新资源
        // 3. 复制 rhs 内容
    }
    return *this;
}
```

为什么返回 `T&`？

为了支持链式赋值：

```cpp
a = b = c;
```

执行顺序是：

```cpp
a = (b = c);
```

### 25.6 static 四种语境

1. 文件作用域 static：限制名字只在当前文件可见。
2. 函数内 static：局部作用域，全程序生命周期，只初始化一次。
3. static 成员变量：属于类，所有对象共享，需要类外定义。
4. static 成员函数：没有 `this`，只能直接访问 static 成员。

典型考题：

```cpp
class A {
    static int count;
public:
    A() { ++count; }
    static int getCount() { return count; }
};

int A::count = 0;
```

若忘记 `int A::count = 0;`，可能链接错误。

### 25.7 运算符重载：成员还是非成员

必须是成员：

- `operator=`
- `operator[]`
- `operator()`
- `operator->`
- `operator->*`

通常建议非成员：

- 对称二元运算符，如 `+`、`-`、`==`、`<`，尤其需要左右两边都允许类型转换时。

例：

```cpp
Integer operator+(const Integer& lhs, const Integer& rhs);
```

### 25.8 前置/后置 ++

```cpp
T& operator++();    // ++x
T operator++(int);  // x++
```

后置版本的 `int` 是哑参数，用于区分签名。前置返回修改后的自身引用；后置返回修改前的副本，因此通常更贵。

### 25.9 `operator[]` 为什么返回引用

```cpp
T& Vector<T>::operator[](int i) {
    return elements[i];
}
```

如果返回值而不是引用：

```cpp
v[0] = 10; // 无法修改容器内部元素
```

应同时提供 const 版本：

```cpp
T& operator[](int i);
const T& operator[](int i) const;
```

### 25.10 `explicit` 必考

```cpp
class PathName {
public:
    PathName(string s);
};

void open(PathName p);
open("a.txt"); // 可能发生隐式转换
```

如果不希望这种自动转换：

```cpp
explicit PathName(string s);
```

`explicit` 用于防止单参数构造函数导致意外隐式转换。

### 25.11 转换运算符谨慎使用

```cpp
class Rational {
public:
    operator double() const;
};
```

它会让对象自动转成 double，方便但可能导致重载解析混乱。考试答题可写：转换运算符应谨慎使用，优先显式转换，避免函数调用中发生意外匹配。

## 26. 第 9-12 讲增强考点：流、模板、STL、迭代器

### 26.1 `operator<<` 和 `operator>>` 为什么返回流引用

输出：

```cpp
ostream& operator<<(ostream& os, const T& obj) {
    os << obj.field;
    return os;
}
```

输入：

```cpp
istream& operator>>(istream& is, T& obj) {
    is >> obj.field;
    return is;
}
```

返回引用是为了链式调用：

```cpp
cout << a << b;
cin >> x >> y;
```

它们通常应是非成员函数，因为左操作数是 `ostream` 或 `istream`，不是你的类对象。

### 26.2 manipulator 考点

`endl` 和 `'\n'` 不完全一样：

- `'\n'` 只换行。
- `endl` 换行并 flush。

`setw` 只影响下一次输出字段宽度；`setfill`、`setprecision` 等状态通常会保持。

### 26.3 模板实例化

模板本身不是函数/类实体，而是生成函数/类的模式。

```cpp
template<class T>
T max(T a, T b) { return a < b ? b : a; }

max(1, 2);       // 实例化 max<int>
max(1.0, 2.0);   // 实例化 max<double>
```

`max(1, 2.0)` 不能直接推导一个统一的 `T`，除非显式指定或提供重载。

### 26.4 模板定义为什么通常放头文件

编译器实例化模板时必须看到完整定义。如果只有声明没有定义，使用处无法生成具体代码，可能链接失败。因此模板函数和模板类成员函数通常写在头文件中。

### 26.5 非类型模板参数

```cpp
template<class T, int N>
class Array {
    T data[N];
};

Array<int, 10> a;
```

`N` 必须是编译期常量表达式。`Array<int, 10>` 和 `Array<int, 20>` 是不同类型。

### 26.6 STL 三件套

必须能用一句话解释：

- Container：保存数据，如 `vector`、`list`、`map`。
- Iterator：像指针一样指向容器元素，提供统一遍历接口。
- Algorithm：通过迭代器处理数据，如 `find`、`sort`、`copy`。

STL 的核心思想是算法不直接依赖具体容器，而是依赖迭代器区间。

### 26.7 容器选择题

| 场景 | 推荐容器 | 原因 |
|---|---|---|
| 需要按下标随机访问 | `vector` | 连续存储，随机访问 O(1) |
| 主要在尾部添加 | `vector` | `push_back` 平均高效 |
| 已有迭代器位置，频繁中间插入删除 | `list` | 插入删除不搬移其他元素 |
| 需要 key-value 查找 | `map` | 按 key 组织 |
| 只关心是否存在且不重复 | `set` | 集合语义 |
| 先进先出 | `queue` | 队列语义 |
| 后进先出 | `stack` | 栈语义 |
| 每次取最大/最小优先级 | `priority_queue` | 优先队列 |

注意：`list` 不是“总比 vector 插入删除快”。如果找位置需要线性遍历，整体未必更快。考试答题要结合访问模式。

### 26.8 `vector` 和 `list` 迭代器差异

`vector` 迭代器通常是随机访问迭代器：

```cpp
it + 3;
it < v.end();
```

`list` 迭代器是双向迭代器：

```cpp
++it;
--it;
it != lst.end(); // OK
it < lst.end();  // 错
```

PPT 第 7 讲图像页中特别强调：遍历 list 用 `p != s.end()`，不能用 `p < s.end()`。

### 26.9 `map[]` 陷阱

```cpp
map<string, int> m;
if (m["bob"] == 0) {
}
```

如果 `"bob"` 不存在，这行会插入 `"bob"`，值为默认构造的 `int`，也就是 0。只检查存在性时：

```cpp
if (m.count("bob") != 0) {}
```

或现代 C++：

```cpp
if (m.find("bob") != m.end()) {}
```

### 26.10 iterator_traits 的理解题

问题：为什么不直接写 `I::value_type`？

答：普通迭代器类型可以定义 `value_type`，但原生指针如 `int*` 没有成员类型 `value_type`。`iterator_traits<I>` 通过模板特化统一提取迭代器相关类型，使算法既能接受容器迭代器，也能接受原生指针。

核心代码：

```cpp
template<class I>
struct iterator_traits {
    typedef typename I::value_type value_type;
};

template<class T>
struct iterator_traits<T*> {
    typedef T value_type;
};
```

### 26.11 iterator category 与算法优化

`advance(it, n)` 对不同迭代器有不同实现：

- input iterator：只能循环 `++it`。
- bidirectional iterator：可 `++it` 或 `--it`。
- random access iterator：直接 `it += n`。

这体现了 tag dispatch：用 iterator category 选择更高效实现。

### 26.12 `typename` 为什么出现

模板中：

```cpp
typename iterator_traits<I>::value_type x;
```

`typename` 告诉编译器后面是一个类型名。因为模板参数未确定时，编译器不知道 `iterator_traits<I>::value_type` 是类型还是静态成员。

这是模板题中常见补全点。

## 27. 第 13-15 讲增强考点：异常、智能指针、casts、命名空间

### 27.1 异常适合处理什么

适合：

- 调用点无法本地处理的错误。
- 构造函数失败。
- 库函数无法决定如何恢复的错误。
- 下标越界、分配失败、文件打不开等异常情况。

不适合：

- 普通循环退出。
- 正常业务分支。
- 可以简单用 `if` 本地处理的情况。

### 27.2 throw/catch 控制流

```cpp
try {
    throw DerivedError();
} catch (const DerivedError& e) {
} catch (const BaseError& e) {
} catch (...) {
}
```

handler 从上到下匹配，所以派生类异常要写在基类异常前。否则基类 catch 会先捕获，派生类 catch 永远到不了。

### 27.3 catch by reference

推荐：

```cpp
catch (const std::exception& e)
```

原因：

- 避免拷贝。
- 避免 slicing。
- 可捕获派生异常并保留动态类型信息。

不推荐：

```cpp
catch (std::exception e) // 可能 slicing
```

### 27.4 构造函数抛异常

如果构造函数抛异常：

- 该对象本身没有构造完成，因此不会调用该对象析构函数。
- 已经构造完成的成员对象会被自动析构。
- 构造函数体中手动获得的裸资源可能泄漏，因此应使用成员对象或智能指针管理。

答题关键词：partially constructed object、member destructors、RAII。

### 27.5 析构函数抛异常

析构函数不要抛异常。尤其在 stack unwinding 过程中，如果析构函数再抛异常，会调用 `std::terminate()`。

安全做法：析构函数内部捕获并处理所有异常，或设计释放操作不抛异常。

### 27.6 异常安全的银行账户例子

PPT 的 BankAccount 例子：

```cpp
reduceBalance(amount);
prepareCash(); // throws
releaseCash();
```

如果 `prepareCash()` 抛异常，余额已经减少但现金没发出，对象状态错误。

改进思路：

1. 先执行可能失败但不改变状态的操作。
2. 确认成功后再提交状态变化。
3. 或使用事务/回滚对象。

答题时写：

```cpp
prepareCash();
reduceBalance(amount);
releaseCash();
```

但还要说明真实程序要考虑 `releaseCash()` 是否也可能失败。

### 27.7 RAII 是异常安全核心

RAII：资源获取即初始化。资源交给对象管理，对象析构释放资源。

例：

```cpp
void f() {
    std::ifstream file("a.txt");
    std::vector<int> v(100);
    // 即使中途抛异常，file 和 v 的析构也会自动释放资源
}
```

RAII 的考试价值：它把资源释放绑定到对象生命周期，避免手动 `delete`、`close` 遗漏。

### 27.8 智能指针与所有权

```cpp
unique_ptr<T> p; // 独占所有权
shared_ptr<T> p; // 共享所有权，引用计数
weak_ptr<T> p; // 弱引用，不增加引用计数
```

选择：

- 默认用 `unique_ptr` 表示唯一拥有。
- 多个对象确实共享生命周期时用 `shared_ptr`。
- 为避免 shared_ptr 循环引用，用 `weak_ptr`。

### 27.9 引用计数题怎么做

看到：

```cpp
String x("abcdef"); // count = 1
String y = x;       // count = 2
x = "hello";        // x 指向新 rep；旧 rep count 变 1
```

步骤：

1. 每次拷贝智能指针，目标对象引用计数 +1。
2. 每次智能指针离开或改指向，旧对象引用计数 -1。
3. 计数到 0，删除被管理对象。

### 27.10 invasive 与 non-intrusive

PPT 的 `UCObject` 方案是 invasive，因为被管理对象必须继承 `UCObject`，计数器嵌在对象内部。

`std::shared_ptr` 是 non-intrusive，被管理类型不需要继承某个基类；引用计数通常放在控制块中。

### 27.11 named casts 对比

| cast | 用途 | 风险 |
|---|---|---|
| `static_cast` | 普通显式转换、相关类型转换 | 下行转换不做运行时检查 |
| `dynamic_cast` | 多态层次安全下行转换 | 需要多态基类，有运行时开销 |
| `const_cast` | 添加/移除 const/volatile | 修改真正 const 对象是未定义行为 |
| `reinterpret_cast` | 低层位模式重解释 | 最危险，通常不可移植 |

C 风格 cast 不推荐，因为它可能等价于多种 cast，读者看不出意图。

### 27.12 dynamic_cast 必须有多态基类

```cpp
struct A { virtual ~A() {} };
struct B : A {};

A* p = new B;
B* q = dynamic_cast<B*>(p); // OK
```

如果 `A` 没有任何虚函数，`dynamic_cast` 下行转换不能用于这种运行时类型检查。

### 27.13 多重继承为什么危险

多重继承会带来：

- 成员名字冲突。
- 重复基类子对象。
- 对象内存布局复杂。
- 构造和析构顺序复杂。
- virtual base 带来额外开销。

PPT 的态度是：一般说 no。相对安全的用途是继承多个纯接口类。

### 27.14 虚基类解决什么

钻石继承：

```cpp
struct B { int x; };
struct D1 : public B {};
struct D2 : public B {};
struct M : public D1, public D2 {};
```

`M` 中有两份 `B`。如果希望共享一份：

```cpp
struct D1 : virtual public B {};
struct D2 : virtual public B {};
```

虚基类解决重复基类子对象问题，但有空间和运行时开销。

### 27.15 namespace 考点

命名空间是名字作用域，用于避免全局名字冲突。

```cpp
namespace MyLib {
    void foo();
}

MyLib::foo();
```

`using declaration`：

```cpp
using MyLib::foo;
foo();
```

`using directive`：

```cpp
using namespace MyLib;
```

区别：

- using declaration 只引入一个名字，来源明确。
- using directive 引入整个命名空间，方便但可能造成歧义。

歧义题：

```cpp
namespace X { void y(); }
namespace Y { void y(); }
using namespace X;
using namespace Y;
y();    // ambiguous
X::y(); // OK
```

命名空间是开放的：同一 namespace 可在多个文件中继续添加声明。

## 28. 一页式高频考点总表

| 考点 | 必须会说的话 | 常见坑 |
|---|---|---|
| 指针 vs 引用 | 指针是地址变量，可为空可改指向；引用是别名，必须初始化不可换绑 | `r = y` 是改对象值，不是换引用 |
| `const` 指针 | 看 const 修饰指针还是指向对象 | `const int*` 和 `int* const` 混淆 |
| 构造函数 | 创建对象时自动调用，无返回类型 | 写成 `void X()` |
| 初始化列表 | 在构造函数体前初始化成员和基类 | const/ref 成员不能在函数体赋值 |
| 析构函数 | 对象销毁时自动调用，释放资源 | 通过基类指针删除派生对象但析构非 virtual |
| 组合 | has-a，成员对象构成整体对象 | 把拥有关系错写成继承 |
| 继承 | is-a，public 继承表示替换 | private 继承不表达普通 is-a |
| 多态 | 基类指针/引用 + virtual + override | 按值传递导致 slicing |
| 拷贝构造 | 用已有对象创建新对象 | 和 assignment 混淆 |
| 深拷贝 | 复制资源内容而非地址 | 裸指针默认拷贝导致 double delete |
| static 成员 | 属于类，所有对象共享 | 静态成员变量忘记类外定义 |
| 运算符重载 | 本质是函数调用 | 滥用导致语义不清 |
| `operator=` | 返回 `T&`，检查自赋值 | 资源类不写导致浅拷贝 |
| stream 重载 | 非成员函数，返回流引用 | 忘记 `return os/is` |
| 模板 | 类型参数化，编译期实例化 | 模板定义只放 cpp 导致链接失败 |
| STL | 容器 + 算法 + 迭代器 | `map[]` 意外插入 |
| 迭代器 | 泛化指针，连接算法和容器 | `list` 迭代器不能 `<` |
| traits | 提取迭代器类型信息 | 忘记原生指针没有 `value_type` |
| 异常 | 分离错误处理和正常逻辑 | 用异常做普通控制流 |
| RAII | 对象生命周期管理资源 | 手动释放在异常路径遗漏 |
| 智能指针 | 用对象管理堆资源 | `shared_ptr` 循环引用 |
| named casts | 表达转换意图 | C 风格 cast 太粗暴 |
| namespace | 避免名字冲突 | `using namespace` 导致歧义 |

## 29. 代码题快速判定清单

拿到代码题时按这个顺序检查：

1. 是否有对象定义？如果有，写出构造顺序。
2. 是否有作用域结束或 `delete`？如果有，写出析构顺序。
3. 是否按值传参或返回？如果有，考虑 copy constructor。
4. 是否出现 `=` 且左边对象已存在？如果有，考虑 assignment operator。
5. 是否通过基类指针/引用调用函数？如果函数 virtual，看真实类型；否则看静态类型。
6. 是否通过基类指针 delete？检查基类析构是否 virtual。
7. 是否有裸指针成员？检查深拷贝、析构、赋值。
8. 是否有 `const` 对象？只允许调用 const 成员函数。
9. 是否有重载函数或重载运算符？判断最佳匹配和成员/非成员形式。
10. 是否有模板？判断模板参数能否推导，是否需要 exact match。
11. 是否使用 STL？检查迭代器类型、失效、`end()`、`map[]` 插入。
12. 是否有异常？检查异常传播、catch 顺序、RAII、析构是否抛异常。

## 30. 可直接背诵的简答题答案

### 30.1 封装、抽象、模块化

封装是把数据和操作数据的函数放在同一个对象中，并通过访问控制隐藏实现细节，只暴露稳定接口。抽象是忽略低层实现细节，只关注问题的高层模型。模块化是把复杂系统分解成多个相对独立的模块。三者共同目标是降低复杂度、减少耦合、提高可维护性。

### 30.2 构造函数和析构函数

构造函数在对象创建时自动调用，用于初始化对象并建立有效状态；析构函数在对象销毁时自动调用，用于释放资源。构造函数可重载、无返回类型；析构函数无参数、无返回类型，一个类只有一个析构函数。若类作为多态基类使用，析构函数应为 virtual。

### 30.3 继承和组合

组合表示 has-a，用已有对象作为成员构造更大的对象；继承表示 is-a，用派生类复用基类接口和实现。优先使用组合，只有当派生类确实可替换基类时才使用 public 继承。组合更弱耦合，继承更强调类型层次。

### 30.4 多态

多态允许不同派生类对象通过同一个基类接口表现出不同行为。C++ 中通过 virtual 函数、基类指针或引用、动态绑定实现。多态提高扩展性，但要求注意虚析构、避免对象切片，并接受 vtable/vptr 带来的少量开销。

### 30.5 拷贝构造和赋值运算符

拷贝构造用于用已有对象初始化新对象，典型签名是 `T(const T&)`；赋值运算符用于两个已经存在的对象之间赋值，典型签名是 `T& operator=(const T&)`。资源管理类如果使用裸指针，通常需要自定义析构函数、拷贝构造函数和赋值运算符，避免浅拷贝导致 double delete 或内存泄漏。

### 30.6 模板和 STL

模板允许类型作为参数，实现泛型编程。函数模板和类模板在编译期按具体类型实例化。STL 是标准模板库，核心由容器、算法、迭代器组成。容器保存数据，算法通过迭代器处理数据，迭代器把算法和具体容器解耦。

### 30.7 异常和 RAII

异常用于处理运行时错误，使错误处理代码和正常逻辑分离。`throw` 抛出异常，`try/catch` 捕获异常。RAII 将资源绑定到对象生命周期，对象构造时获取资源、析构时释放资源，因此即使异常发生，栈展开也能自动清理已构造对象，是 C++ 异常安全的重要基础。
